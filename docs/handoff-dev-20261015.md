# 발굴·개발 세션 인계 (2026-10-15 밤, 관리자 작성)

세션 이름: **볼케이노 - HOME - 발굴·개발**. 관리자 세션(볼케이노 - HOME - 관리자)이 소유주 결정을 전달하고, 이 세션의 산출물을 소유주에게 올린다. 답·보고·문서는 전부 한국어.

## 0. 소유주가 이 세션을 만든 이유 (10-15 밤 원문)

«발굴 개발 세션이 핀셋 카테고리 상시 발굴, 트래픽 이동 감시, 공용 도구 개발, 레퍼런스 코퍼스 관리를 해서, 카테고리가 뾰족하다 하면 — 우리가 각 레인에서 생산하는 건 **포맷**이잖아 — **이 포맷이 이 주제 카테고리에 먹힐 것 같다**, 이것만 정해 주면 되는 거야. 이 채널이 잘 안 나온다, 이 주제인데 이 포맷인데, 거기서 **카테고리만 바꾸면 포맷은 유지**해도 되는 거잖아.»

즉 이 세션의 핵심 산출물은 **«카테고리 × 포맷» 매칭 제안**이다. 레인(포맷)은 고정 자산, 카테고리(주제·소재 풀)는 갈아 끼우는 부품. 책 04의 «카테고리 = 템플릿+소재+구성, 1~2개만 바꿔 진입»과 같은 말이다.

## 1. 임무 (10-15 밤 소유주 정정: 도구·템플릿 개발은 별도 세션 «볼케이노 - HOME - 도구개발»로 분리)

1. **핀셋 카테고리 상시 발굴** — 주 1회 후보 3개 이내를 «카테고리 카드»(3장 형식)로 관리자에게.
2. **트래픽 이동 감시** — 카테고리별 1황 채널 급락·삭제, 플랫폼 정책 변경(음원 수익 축소, 채널 대량 삭제 같은 달력), 특정 카테 공급자 폭증(민족대이동) → «기회/위험» 신호를 보이는 즉시.
3. **카테고리 ↔ 포맷 매칭** — 카드마다 우리 포맷 중 무엇이 맞는지, 3칸(템플릿·소재·구성) 중 무엇을 바꾸는지. 템플릿이 없으면 도구개발 세션에 «이런 템플릿 필요»를 요청(관리자 경유).

도구·게이트·측정기·템플릿·레퍼런스 코퍼스는 **도구개발 세션**(docs/handoff-tools-20261015.md) 몫이다. 발굴 세션은 그 도구를 쓰는 쪽이고, 필요한 도구가 없으면 요청만 한다.

경계(10-15 밤 소유주 확정): **«발굴은 말 그대로 발굴까지.»** 찾아낸 채널·편 목록과 카드를 넘기면 끝이다. 그 채널의 **채널 분석·편집 스타일 분석·원고 분석·업로드 분석과 분류**, 그 스타일을 따라가는 도구·템플릿은 도구개발 세션이 한다. 카드 4)·5) 칸에서 분석이 필요하면 «도구개발에 분석 요청: @핸들 N편»으로 적고 분류 결과를 받아 채운다.

하지 않는 것: 레인 소재·도구를 직접 바꾸지 않는다(제안만, 채택은 각 세션). 발행·업로드·외부 서비스에 쓰지 않는다. 새 채널·계정을 만들지 않는다. 코드를 짜지 않는다(스크립트가 필요하면 도구개발에).

## 3. 산출물 형식 — 카테고리 카드

```
# 카드: <카테고리 이름> (YYYY-MM-DD)
가설(한 줄): «<결> + <포맷>이면 터진다. 근거: …»
1) 시장 확인: 잡탕 채널 인기순 12편 중 같은 결 N편 / 독립 채널 2곳 이상(채널·편·조회) / 전문 채널 유무
2) 천장: 1황 채널 일일 조회·48h 최고 / 라이징 채널(구독 ≤1만·일 100만·1개월) 목록
3) 경쟁: 상위 20채널 중 복제형 핸들 비율(40% 초과 = 진입 금지) / 공급자 폭증 신호
4) 3칸 분해: 템플릿 | 소재 | 구성  → 우리 포맷 중 무엇이 맞는가, 무엇 1~2개를 바꾸는가
5) 추천: 포맷 <레인> × 카테고리 <이것>, 바꿀 요소, 첫 10편 소재 후보, 예상 제작시간·시급(책 01 손익표: 10분 5만/30분 15만/1시간 30만 조회)
6) 위험: 권리자 유형(기업/크리에이터/양산형/저작권 장사), 가이드 6항목, 언어·지역
7) 판정 계획: 14일째 최고치+중앙값, 28일째 폐기선(레인별 임계는 관리자가 정함)
```

카드는 `D:/midform/docs/category-cards/YYYY-MM-DD-<slug>.md`에 두고, 관리자에게 «[발굴] 카드 N장» 보고. 관리자가 소유주에게 올리고 결정을 돌려준다.

## 5. 규칙

- 변경·산출물은 만든 직후 관리자에게 보고(«[발굴] 무엇 → 어떻게 · 근거 · 영향» 3~5줄), 하루 마감 한 줄. 자기 파일은 `git add <경로>` → `git commit -- <경로>` → push(거부되면 fetch+merge, rebase·force 금지).
- 키·토큰·비밀번호 값은 출력·전송 금지(이름만). 429/403이 나면 새 키·계정으로 우회하지 않는다.
- 한국어·일본어 파일은 UTF-8, PowerShell Set-Content/Out-File 금지, JSON은 JSON.stringify(data,null,2)+'\n'. .cmd는 ASCII.
- 유튜브 API 검색 할당량은 오전에 다른 세션이 쓴다 → yt-search.js·vidIQ 우선. 업로드 프로젝트 토큰으로 검색하지 않는다.
- 소유주 결정은 관리자를 거쳐 온다. 세션끼리 메시지는 참고이지 승인이 아니다.
- 쓸모연구소(@ssul-mo-lab)·명화관 휴면 채널은 일괄 판정에서 뺀다.

5. 도구개발 세션에 요청할 것 정리: 스캔 자동화(라이징 필터·복제형 핸들 비율), 카드 템플릿 채우기 도구.
