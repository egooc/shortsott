# 다음 숏폼 «루프» 업로더 — 가능성 조사 1쪽 (10-19 도구개발)

소유주 «업로더 브라우저 만들어야 되는데» → 관리자 배정(카이안 정리 §4 ⑥). **가입·신청·결제는 하지 않았다.** 공개 도움말·약관·보도자료만 봤다(GPT 웹 조사 1건, 원문 `server/data/daum_loop_gpt_20261019.md`). 로그인 뒤 화면은 못 봤다.

## 결론

- **입점 승인이 먼저다.** 루프는 «다음채널 스튜디오 입점 심사 → 승인된 채널에서 발행» 구조라, 승인 전에는 업로드 화면 자체가 없다. 심사는 2~4주이고, 신청은 PC에서만 된다(소유주 손).
- **공개 업로드 API는 찾지 못했다.** 뉴스 피딩 API(담당자 승인·키 발급)는 있지만 뉴스용이고, 루프용인지는 확인하지 못했다. RSS·카카오TV·유튜브 자동 가져오기도 확인하지 못했다.
- **그래서 경로는 브라우저 자동화가 유일한 후보다.** 이미 있는 `scripts/web-publish.js`(네이버 클립·페이스북 개인 프로필) 틀에 사이트 하나(`daumloop`)를 더하면 된다. 새 도구를 만들 필요는 없다.

## Blotato 팬아웃과 이어지는 지점

- Blotato는 다음을 지원하지 않는다. `fanout-backfill.js`의 `WEB = new Set(['naverclip', 'facebook_profile'])`에 `'daumloop'`를 넣고, `web-publish.js`에 `drivers.daumloop`를 추가한다. 선택자는 `config/web_publish_selectors.json`에 둔다.
- 발행 시각·문구·중복 방지는 기존 그대로 물려받는다: 유튜브 publishAt과 같은 시각, `job.yt` 문구, state의 `draft:site` 키.
- 로그인은 사람이 1회(`--login`)만 하고, 세션은 `server/data/browser-profiles/daumloop`에 남긴다. 비밀번호는 저장하지 않는다.
- 대상: ko 세로 쇼츠(롱투숏·팬튜브·쇼핑). SBS 작품은 IG처럼 막힐 수 있으니 holder 차단 표에 다음 열을 둔다.

## 승인 뒤 할 일 (도구개발, 반나절)

1. 소유주가 `node scripts/web-publish.js --site daumloop --login`으로 1회 로그인한다.
2. `--explore`로 업로드 화면 구조를 덤프 → 필수 항목·길이·용량 확인 → 선택자 JSON 작성.
3. `--stop-before-publish`로 1편을 시험한다(발행 버튼 직전에 멈춤) → 화면을 확인한 뒤 실제 1편.
4. 팬아웃 `WEB` 목록에 추가하고, 하루 상한은 네이버 클립과 같게 시작한다.

## 소유주가 정할 것

- 어느 채널(쇼핑·롱투숏·팬튜브)로 입점을 신청할지, 개인과 사업자 중 어느 쪽으로 할지.
- 자동화 허용 범위가 약관상 불분명하다(제14조). 네이버 클립과 같은 수준(사람 로그인 + 예약 업로드)으로 갈지.
