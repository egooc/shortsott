# ref-analyze 설계안 — 레퍼런스 채널 분석 4종 + 분류 (도구개발, 2026-10-16)

> 코드 전 설계안이다. 관리자 확인 뒤 1단계부터 만든다. 근거: handoff-tools 백로그 2·임무 2, 규칙집 W15(벤치 대본 20~100편 → 구조 빈도 → 레인 지침서), 10-15 소유주 «채널·편집 스타일·원고·업로드 분석 → 분류까지가 도구 세션».

## 1. 한 줄

`python scripts/ref_analyze.py @핸들 --lane ko_longshort [--n 40] [--stage 1|2]` → `reference/<lane>/<handle>/` 에 네 표(channel·style·script·upload)와 분류 한 장(`class.md`)을 떨군다. 같은 채널을 다시 돌리면 받은 것은 캐시로 재사용하고 표만 다시 쓴다.

## 2. 표본 고르기 (모든 분석 공통)

- 최근 90일 편 중 공개 3일+ → 조회수로 **상위 20 · 하위 20**(채널이 작으면 상·하위 각 1/3). 4종 분석 모두 «상위군 vs 하위군» 차이로 낸다 — 평균만 내면 «이 채널은 이렇다»에서 끝나고, 무엇이 조회수를 가르는지가 안 나온다.
- 메타: 발굴용 Data API 키(공개 통계만), 채널 토큰은 쓰지 않는다. 영상 받기는 상·하위 표본만(편당 360p, 분석 뒤 지움).

## 3. 분석 4종

| 표 | 무엇을 재나 | 어떻게(기존 도구 재사용) | 비용 |
|---|---|---|---|
| **channel.json** | 구독·총 편수·개설일·30/90일 업로드 수·조회 중앙/분위·퍼짐(상위25÷중앙)·쇼츠/롱폼 비율·3배 넘은 편 비율 | `thread_report.js` 분포 함수·`lane_dist` 식 그대로 | API 수 회 |
| **upload.json** | 요일·시각(KST/JST) 분포, 하루 편수, 연속 업로드 간격, 시리즈(같은 에셋 연속 N편) 길이, 3배 편 직후 같은 결 후속 여부 | publishedAt + 제목 에셋 토큰(`thread_report.titleShape`) | 0 |
| **script.json** (ref-9dim 원고) | 평균 문장 길이·종결어미 분포·후킹까지 문장 수·첫 문장 유형(질문/단정/숫자)·엔딩 유형(닫는 한 줄/CTA/열린 끝)·해설 비중(말한 시간÷길이)·제목 글자수/숫자/물음표·느낌표 | 자막: yt-dlp **자동 자막 먼저**(0원). 없으면 해당 편만 Speechmatics(편당 상한 걸고, 상·하위 각 10편까지). 문장 분할·종결어미는 ko/ja 규칙 사전 | 대개 0원 |
| **style.json** (편집 스타일) | 평균 컷 길이·컷 수/분·첫 컷 길이(0~2초 후킹)·자막 위치/줄 수/글자수·머리띠(상단 띠) 유무·화면 틀(9:16 원본/크롭/레터박스)·킬샷 위치(%)·끝 카드 유무 | 장면전환 `select='gt(scene,0.3)'` + 3~5초 샘플 컨택트 시트(롱폼 비전 표준형), 자막 OCR `ocr_area.py`, 틀은 cropdetect(로고 함정 주의) | 로컬 CPU, AGY 0회 |

- 1단계 = channel·upload·script(자막만으로 끝나는 것). 2단계 = style(영상 받아 재는 것).
- 킬샷 위치·후킹 유형처럼 사람 판단이 섞이는 칸은 값 + 근거 시각을 함께 남겨 눈으로 확인할 수 있게 한다(자동 확정 안 함).

## 4. 분류 (class.md)

- **포맷 카탈로그 코드**(발굴 handoff-dev의 포맷 카드와 같은 이름: 롱투숏·린박스형·어랍숏형·정치 발췌형 …) 하나 + **결 태그** 3~5개(에셋 종류·감정 축·화면 틀).
- **상위군이 하위군과 다른 점 Top 5**를 수치로(예: «상위군 첫 컷 1.1초 vs 하위 2.8초», «상위군 85%가 질문형 첫 문장»). 이게 지침서(W15)와 style-follow(백로그 2-1)의 입력이다.
- **우리 레인 대비 차이**: 같은 레인의 우리 편(`thread_report` 레인 정의)을 같은 표로 재서 나란히 — 1단계는 원고·업로드만, 2단계에 스타일.

## 5. 첫 대상 — A 롱투숏 레퍼런스

- 대상 채널 목록은 A(롱투숏) 담당 세션이 정한다. 도구개발은 채널을 고르지 않는다(발굴·A 몫). 후보 예: rising-scan-01의 @셀tv(예능 클립), A 세션이 모아 둔 국내 롱투숏 벤치.
- A 첫 실행 3채널 기준 예상: API 수십 회, 자동 자막으로 대개 0원, 영상 120편 × 360p ≈ 6GB 임시(분석 뒤 삭제), CPU 장면전환 편당 수십 초.

## 6. 하지 않는 것

- 채널 발굴·후보 고르기(발굴 세션), 중복 판정(소유주 기준 이미지 검색뿐 — 이 도구에 넣지 않음), 인스타·틱톡(유튜브 수치로 판정 규칙), 유료 비전 API.
- 받은 영상·자막은 `reference/` 밖 임시 폴더, 커밋은 표(JSON·md)만. 원본 자막 전문은 커밋하지 않는다(용량·권리).

## 7. 관리자가 정할 것

1. 1단계(원고·업로드·채널) 먼저 내고 2단계(스타일)는 A 결과 본 뒤 — 이 순서로 가도 되는지.
2. 자동 자막이 없는 편의 Speechmatics 사용 상한(제안: 채널당 20편).
3. A 첫 대상 채널 목록을 A 세션에서 받아 줄지, 도구개발이 직접 물을지.
