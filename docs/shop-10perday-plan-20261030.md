# 쇼핑 하루 10편 계획 (10-30 소유주 개편)

개편: 유튜브 쇼핑 채널 5개 × 하루 2편(한 영상 = 한 채널) · 유튜브+인스타만(틱톡·페북 끔) · 링크는 인포크 하나.

## 지금 실측
- 밤 생산 2회차(00:30·03:30) × 2편 = 하루 최대 4편. 실제 10-29 3편, 10-30 4편.
- 한 회차(2편) 약 1시간~1시간 20분, 렌더 잠금 37~51분. 회차 한도 3시간.
- TikHub: 한 편에 13~14회(03:30 회차 2편 27회). 회차 한도 30회 → 한 회차 2편이 상한.
- 한 편 작업 폴더 1.4~1.7GB. D: 여유 17GB.
- 소재 풀: 작년 시즌 75편, 경쟁 판매 레퍼런스 56폴더.

## 하루 10편 안 (추천)
- 회차 5개 × 2편: 00:30·03:30(지금) + 09:30·12:30·15:30(새로). 정치 렌더 18:30~00:30 은 비운다.
- 각 회차 그대로: 잠금·빈 메모리 8GB 확인, 회차당 TikHub 30회, 시즌 첫 편 규칙은 «하루 첫 편»으로.
- 07:20 fill → 채널별 08·18시 2편씩(채널마다 재고 따로). fill 은 채널 5개가 연결된 뒤 바꾼다.

## 병목 (숫자)
1. **유튜브 API 하루 한도** — 업로드 1편 1,600 + 태그·댓글 약 100 → 10편 ≈ 17,000 단위. 기본 한 프로젝트 10,000 → 프로젝트를 나누거나 한도 증설 필요(도구개발·관리자 확인).
2. **디스크** — 10편 × 1.5GB = 하루 15GB, 여유 17GB. 업로드 끝난 편 작업 폴더 정리를 매일 돌려야 함(정리 스크립트 apply 를 fill 뒤로).
3. **TikHub 비용** — 하루 54회 → 135회(2.5배). 10-27 잔액 부족(402)으로 이틀 0편 전례 → 충전 주기 당겨야.
4. **새 채널 업로드 한도** — 인증 전 채널은 하루 업로드 수·15분 길이 제한(우리 편은 35초라 길이는 무관). ko 채널은 하루 4편째에서 막힌 실측 → 채널당 2편이면 여유, 대신 재렌더·교체도 한 칸 씀.
5. **인스타** — Blotato 끔으로 지금 인스타 발행 경로가 없음. 길 정하는 건 도구개발·관리자 몫.
6. **소재 풀** — 시즌 풀 75편은 하루 10편이면 1~2주. 시즌 풀 갱신(검색어 25개 = 2,500 단위)을 주 1회.
7. **낮 메모리** — 낮엔 다른 레인이 돌아 빈 메모리 8GB 미달 대기 가능(10-30 낮 12.5GB). 대기하면 회차 3시간 안에 못 끝날 수 있음.

## 새 채널 연결·인증 순서표 (채널 하나마다)
| 순서 | 할 일 | 누구 |
|---|---|---|
| 1 | 채널 만들기(이름 확정본) · 휴대폰 인증 | 소유주 |
| 2 | 인증 확인(긴 영상·맞춤 썸네일 켜짐) | 소유주 |
| 3 | 연결 `yt-connect.js` (폰 가능: `yt-reauth --url-only` → 코드) | 소유주 클릭 · 쇼핑 세션 실행 |
| 4 | 채널 매핑·용도 등록, fill 에 채널 칸 추가 | 쇼핑 세션 |
| 5 | 프로필 링크에 인포크 하나, 설명란 고정 문구 | 소유주(화면) · 쇼핑 세션(문구) |
| 6 | 첫 3일 웜업: 하루 1편 → 4일째부터 2편 | 쇼핑 세션 |
| 7 | 저조회 자동 비공개 대상에서 14일 유예 | 관리자 |

인증은 연결보다 먼저(인증 전 업로드는 하루 한도가 낮고, 막히면 24시간 롤링으로 안 풀림).
