# 데일리 자동 파이프라인 계획 (2026-08-10 초안 — 결정 대기)

목표: 매일 크론으로 [소재 자동 수집 → 큐 → 배치(다운로드/분석/드래프트)]를
무인 실행. 사람은 CapCut 내보내기와 업로드(Phase 3)만 담당.

## 0. 실측 기반 수율 산식 (2026-08-08/09 배치 + 08-10 테스트런)

- 26개 소스 배치 → 12개 출고 → 하이라이트 39개 (소스당 평균 1.5개, 출고 소스당 ~3.3개)
- 신규 정책 반영(재분석 +12%p, 최소 1개 출고): 출고율 ~60-70% 예상
- **소재 12개/일 큐잉 → 하이라이트 드래프트 15~25개/일 예상**
- **드래프트 12개/일이 목표라면 → 소재 8~9개/일이면 충분**
- 배치 소요: 26개 4.4시간 → 12개 약 2~3시간 (Gemini 분석이 지배 비용)

## 2. 신규 컴포넌트 4개

### H1. 소재 하베스트 (`sourceHarvestService.js` + `npm run daily:harvest`)
1. 검색: yt-dlp `ytsearch` — 쿼리 풀 = 해시태그 문서의 코어 풀 + 카테고리
   쿼리(JA/KO/EN/ZH `台灣工廠`) 로테이션 (하루 4~6쿼리 × 15결과)
2. 필터: 길이 240~1800초(기존 30분 게이트와 정합), 업로드 90일 이내(선택)
3. **중복 제거**: 수집 이력 장부 `server/data/source_harvest_history.json` —
   큐에 들어간 모든 URL 영구 기록. 초기 시드 = 기존 잡 DB의 전체 소스 URL
4. 랭킹: Most Replayed 히트맵 피크 유무/강도(yt-dlp `heatmap`, 도입 문서 B2)
   + 조회수. 상위 N개 선별
5. 임포트: 기존 `import-source-urls` API → 로케일 배분(기본 6/6 JP/KO) →
   `jobs/start` (`enqueue_if_active`로 전일 잡 겹침 안전)

### H2. 적격성 게이트 프로덕션 투입 (승인 필요 — 자동 수집 소스 한정)
- 큐레이션 없는 자동 수집이 시작되는 시점 = 게이트가 필요해지는 시점
  (docs/source-eligibility-spec-2026-08-10.md §0 결론 그대로)
- 위치: 메타데이터 스테이지에서 Gemini 분석 **직전**(소스는 이미 다운로드됨),
  `source_eligibility_probe`(~39초/소스, 0원) 실행
- 컷 기준(보수적 시작): speech_ratio > 0.35 또는 face_dominant > 0.2 또는
  static_ratio > 0.5 → `skipped_source_ineligible` (스킵, 실패 아님)
- **자동 수집 아이템만 enforce** (item_config에 `harvested: true` 마킹),
  수동 큐잉 소스는 게이트 미적용(사람 큐레이션 신뢰). 킬 스위치 별도.

### H3. 크론 등록 (Windows 작업 스케줄러)
- `schtasks /create /sc daily /tn OttogiDailyPipeline /tr "npm run daily:pipeline"`
- daily:pipeline = [스코어카드(전일) → 하베스트 → 배치 시작] 후 즉시 종료
  (배치는 분리 워커라 크론 프로세스와 무관하게 진행)
- 서버 다운이면 하베스트가 감지 → 로그 남기고 스킵 (또는 서버 기동 옵션)

### H4. 데일리 리포트
- `server/output/daily-reports/YYYYMMDD.md`: 어제 잡 요약(성공/스킵/재분석
  횟수) + 스코어카드 ok/review 목록 + 오늘 수집/임포트 목록
- 업로드 작업자가 아침에 이 파일 하나만 보면 되게

- **D. 로케일 배분**: 6/6 고정 vs 다른 비율
