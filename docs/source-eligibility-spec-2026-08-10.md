# 롱폼 소스 적격성 정의 및 검증 게이트 설계 (2026-08-10)

## 0. 캘리브레이션 결과 (2026-08-10 실측) — 게이트는 Phase 1 자동화 대비용

`scripts/source_eligibility_probe.py`(Silero VAD + YuNet + ffmpeg 샘플 모션,
소스당 ~39초, API 0원)를 정답지 15개 소스에 실행한 결과:

- 안정 출고 5개 / **안정 부적격 2개** / 뒤집힘 8개 — **세 그룹의 로컬 신호가
  사실상 동일** (전부 speech≈0, face≈0, motion 10~31, static≈0).
- 안정 부적격(item_001 설탕 공장, item_019)도 카테고리로는 완벽한 공정 영상.
  실패는 카테고리가 아니라 Gemini의 Vision 근거 판정 레벨에서 발생.
- 결론: **사람이 큐레이션하는 현행 Phase 1 바스켓에는 카테고리 게이트가
  걸러낼 것이 없다.** 게이트는 Phase 1 소재 발굴을 자동화할 때(큐레이션
  없는 검색 결과 유입 시) 프리필터로 투입한다. 현행 효율 개선은 아래
  재분석 정책이 담당 (같은 소스 재실행에서 3개가 재시도만으로 회수됨 →
  processJobService 메타데이터 스테이지에 1회 인배치 재분석 도입, 승인됨).

## 1. 우리 하이라이트화가 먹히는 이유 (제품 원리 정의)

출고에 성공한 하이라이트 80여 개(금속 절단·용접·압연, 도자기, 제빵, 기타 제작,
유리, 참치 캔 공정, 수박 착즙, 모터 조립, 인조잔디...)의 공통 구조에서 도출:

1. **완결된 시각적 변형 아크** — 재료가 수 초 안에 눈에 보이게 형태를 바꾸고
   (절단/압착/주조/성형/분리), 그 결과가 화면에 남는다. 후킹→공정→끝이
   언어 없이 이해된다. (아크 우선 철학: CLAUDE.md 2026-08-10 승인 참조)
2. **기계적 리듬과 즉각성** — 첫 1~2초 안에 "무언가 일어나는 중"이 보인다.
   프레스·톱·와인딩의 반복 리듬은 모션 신호(P1 excitement)로 측정 가능하다.
3. **호기심 갭** — "이게 어떻게 만들어지지?" 짧은 설명 블록(~200자)만으로
   시청 가치가 완성되고, 내레이션 전체 번역이 필요 없다.
4. **인물·언어 비의존** — 얼굴/대사가 아니라 손과 기계가 주인공이라
   JP/KR 양쪽 로컬라이즈가 캡션 교체만으로 성립한다.

한 줄 정의: **"언어 없이 이해되는, 수 초 단위의 가시적 재료 변형 아크가
1개 이상 존재하는 영상"** 이 우리의 적격 소스다.

## 2. 카테고리 정의

### 적격 (출고 실적 있음)
| 카테고리 | 예시 (실제 출고분) |
|---|---|
| 금속 가공 | 파이프 절단, TIG 용접, 압연, 단조, 프레스 타발 |
| 식품 대량생산 | 제빵 공정, 참치 캔, 수박 착즙, 츄러스 커팅 |
| 공예 제작 | 도자기 물레, 기타(악기) 제작, 가죽 레이저 가공 |
| 기계 조립/내부 동작 | 모터 와인딩, 로봇 압입, 유압 프레스 |
| 소재 변환 | 유리 성형, 카본 로드, 인조잔디 터프팅 |
| 농수산 수확·가공 | 벼 수확, 꿀 채취, 육류 밀봉 |

### 부적격 (아크가 성립하지 않는 유형)
| 유형 | 이유 |
|---|---|
| 얼굴/대사 중심 (브이로그, 인터뷰, 리액션) | 인물·언어 의존 → 원리 4 위반 |
| 스토리/스킷/감성 노동 영상 ("hard work" 계열) | 변형 아크 없음, 감정이 주제 |
| 컴필레이션 (여러 공정 나열) | 단일 연속 아크가 없음 → 원리 1 위반 |
| 정적 과정 (긴 건조/대기, 강의, 설명 위주) | 첫 2초 즉각성 없음 → 원리 2 위반 |
| 결과가 안 보이는 반복 노동 (운반, 청소) | 결과 노출 없음 → 원리 1 위반 |

## 3. 검증 게이트 설계 (2단계) — 오픈소스 조립 (2026-08-10 조사)

### Stage A — 전부 로컬 신호, API 비용 0원 (소스당 ~1분 목표)

| 게이트 기준 | 도구 | 라이선스 | CPU 비용 |
|---|---|---|---|
| `static_ratio` (정적/저활동) | 기존 P1 `audio_motion_score.py` — 샘플 구간(10초×12곳) | MIT 산식 재구현 (보유) | 초 단위 |
| `speech_ratio` (대사 중심) | **Silero VAD** — 1~2MB ONNX, 30ms 청크당 <1ms | MIT | 오디오 전체도 수 초 |
| `face_ratio` (얼굴 주도) | **OpenCV YuNet** (`face_detection_yunet_2023mar.onnx`) — 샘플 프레임 30장에서 얼굴 크기·빈도 | MIT | ms/frame |
| `category` 제로샷 투표 | **SigLIP / OpenCLIP** — 샘플 프레임 30장 vs 카테고리 텍스트 프롬프트("industrial machine processing material", "person talking to camera", ...) | Apache-2.0 / MIT | 프레임당 수백 ms → 30장 ~10초대 |
| 시청자 검증 (Phase 1) | **yt-dlp `heatmap`** (Most Replayed) — 기존 도입 문서 B2 계획 그대로 | yt-dlp | API 0원 |

교훈 반영: TransNetV2 실패 원인은 "전체 영상 신경망 스캔". 여기선 모든 신경망
추론이 **샘플 프레임/청크에만** 닿는다 — 소스 길이와 무관하게 상한이 고정된다.
speech-ratio 적응 원칙(<0.35면 시각 신호 우선)은 hotclip/clips-studio 스펙
재구현(도입 문서 C2-3, AGPL 코드 미복사)을 따른다.

### Stage B — Gemini 경량 분류 (Stage A가 `uncertain`일 때만)
- `visible_transformation` / `result_reveal_potential`은 순수 신호로 판별 불가 —
  Stage A 로컬 신호로 명백한 부적격을 걸러낸 뒤, 애매한 소스만 저해상도
  프록시로 짧은 분류 호출 1회 (풀 후보 분석의 1/10 이하 비용).
- 판정: `eligible` / `ineligible(사유)` / `uncertain→eligible 취급`

`ineligible` → `skipped_source_ineligible`로 아이템 스킵 (풀 분석 비용 절감:
지난 배치 기준 28개 중 6개 × 5~10분). 배치는 계속 진행 (기존 스킵 규약).

### 중요 설계 근거 — 같은 소스 재실행 실측 (2026-08-08 vs 08-09 배치)
같은 26개 소스를 두 번 돌린 결과 판정 뒤집힘 7건:
- 1차 "후보 없음" → 2차 출고: item_003, 014, 026
- 1차 출고 → 2차 "후보 없음": item_010, 015, 016, 025

즉 "후보 없음"의 상당수는 소스 속성이 아니라 **분석 분산**이다. 따라서:
1. 게이트의 `uncertain`은 버리지 않고 풀 분석으로 통과시킨다.
2. **섀도 모드 우선**: 첫 1~2배치는 게이트가 판정을 기록만 하고 버리지 않는다.
   섀도 판정 vs 실제 출고 결과를 대조해 오탐률(적격인데 ineligible 판정)을
   확인한 뒤 강제 모드로 전환한다. 오탐 = 좋은 소스를 자동으로 버리는 사고.
3. 풀 분석 "후보 없음"에는 게이트와 별개로 **1회 자동 재분석** 정책이
   효율에 더 클 수 있다 (뒤집힘 3건은 재시도만으로 회수 가능했다).

## 4. 배치 위치와 격리

- 신규 서비스 `sourceEligibilityService.js` (게이트 로직 전부),
  Phase 2 메타데이터 스테이지 시작부에서 호출. 보호된 선택 경로
  (`pickHighlightWindows` 등)는 건드리지 않는다.
- Phase 1(소재 발굴)에는 게이트 결과를 표시만 (선택은 사람이 유지).
- 게이트 판정은 `item_config.source_eligibility`에 기록 (스코어카드가 읽음).
- 킬 스위치: `SOURCE_ELIGIBILITY_GATE=0`, 섀도/강제: `SOURCE_ELIGIBILITY_MODE=shadow|enforce`.
