# 쇼핑쇼츠 시스템 기술 명세서
## 클로드 코드 자동화 기반 문서 (편집 툴 비종속)

> 소유주 제공 2026-09-29. 원문 그대로 보존한다. 현재 파이프라인과의 대조는 맨 끝 「부록: 현 상태 대조」.

목적: 쇼핑쇼츠 운영의 전 구조를 툴에 종속되지 않은 명세로 정의한다. 각 파트는 "규칙(WHAT) → 근거(WHY) → 데이터 규격(SCHEMA)" 순으로 기술하며, 자동화 대상 구간은 [AUTO] 태그로 표시한다.

# 1. 시스템 아키텍처

## 1-1. 계정/채널 모델

```
계정(Account) = 하나의 정체성(닉네임/카테고리) 단위
채널(Channel) = 플랫폼 단위 (YouTube, Instagram, TikTok, Facebook, Threads, Naver Clip)

Account (1) ──< Channel (N)
Account (1) ──< Content (N) ── 각 Content는 소속 Account의 채널들에만 배포
```

**불변 규칙:**
- 계정 간 콘텐츠 공유 절대 금지. 계정 A의 영상은 계정 A 산하 채널에만 업로드 (스팸/재사용 판정 + 알고리즘 카테고리 혼란 방지)
- 계정당 카테고리 1개 고정, 최소 8주 불변 (알고리즘 학습 리셋 방지)
- 플랫폼 간 자동 교차게시 기능 미사용 (네이티브 업로드만. 교차게시 콘텐츠는 해당 플랫폼 알고리즘이 온전한 자체 콘텐츠로 취급하지 않아 성장 억제)
- 계정 센터/연동으로 계정들을 묶지 않음 (연쇄 정지 방지). 이메일 다중 동시 본인인증 금지 (순차 인증)

## 1-2. 폴더 규격

```
/workspace
  /{account_code}            # 예: A, B, C (실명 채널명 사용 금지 — 위임 대비 익명화)
    /{product_id}            # 예: A-0031
      /01_source             # 원본 소스 영상 (복수)
      /02_audio              # TTS 출력물
      /03_script             # 대본 (원본 추출본 + 재생성본)
      /04_edit               # 편집 프로젝트/중간 산출물
      /05_final              # 완성본 (플랫폼별 변형 포함)
      meta.json              # 아래 스키마
```

**meta.json 스키마:**
```json
{
  "product_id": "A-0031",
  "account": "A",
  "category": "kitchen",
  "coupang_url": "",
  "affiliate_url": "",
  "source_urls": [],
  "source_platform": "douyin|xiaohongshu|kuaishou",
  "benchmark_ref": "레퍼런스 영상 URL(있을 경우)",
  "content_type": "product|spread",      // 상품용 | 확산용
  "script_version": 1,
  "cta_variant": "comment|profile|tag",  // 플랫폼별 CTA 분기
  "status": "sourced|scripted|edited|scheduled|published",
  "scheduled_at": "",
  "published": { "youtube": {"url":"","at":""} },
  "youtube_dup_checked": true            // 소스 중복 검색 완료 여부
}
```

## 1-3. 시트 이원화 구조 (위임 보안)

| 시트 | 접근자 | 내용 |
|---|---|---|
| **마스터 시트** | 본인 전용 | account_code ↔ 실제 채널명/URL 매핑, 제휴 링크, 수익 정산, 채널별 KPI |
| **운영 시트** | 프리랜서 | product_id, 작업 상태, 폴더 경로, 소스 URL, 마감기한. 채널 실명/링크/수익 정보 일체 노출 안 됨 |

원칙: 운영 시트만 봐서는 "어느 채널에 올라가는 무엇인지" 알 수 없어야 한다. 마스터에 입력하면 운영 시트에는 익명 키만 반영. [AUTO: 두 시트 동기화]

# 2. 소싱 파이프라인

## 2-1. 이중 소싱 전략

**주력 — 상품 우선(Product-First), 물량의 60~100%:**
```
쿠팡 급상승 상품 선정 → 상품의 해외 소스 영상 확보 → 제작 → 정확히 그 상품에 태그/링크
```
근거: 이미 팔리는 상품에서 출발하므로 전환율 하단이 보장됨. 조회수 도박이 아니라 매출 설계.

상품 선정 기준: 판매 급상승 + 로켓배송 + 리뷰 급증 + 타겟(30~50대 여성 생활재) 적합. [AUTO: 쿠팡 카테고리별 급상승 상품 수집·후보 리스트 생성]

**보조 — 벤치마킹 소싱(Content-First):**
레퍼런스 계정 순찰에서 "튄 영상" 발견 → 상품 역추적 → 상품 우선 루프에 편입.

## 2-2. 레퍼런스 계정 스코어링

```
성과율 점수 = 팔로워(구독자) 수 / 게시물 수
```
- 계정당 카테고리별 10~20개 레퍼런스 유지, 주 1회 스코어 갱신, 하위 교체
- 활성 조건: 최근 1~3일 내 업로드 지속 계정만
- 순찰 판정: "그 계정의 **평균 조회수 대비** 튄 영상"만 소싱 후보 등재 (절대값 아님)
- 인스타 레퍼런스는 소싱 전용 계정으로 팔로우해 피드 순찰 (개인/운영 계정과 분리 — 알고리즘 훈련 오염 방지)
- [AUTO: 유튜브 레퍼런스는 채널 RSS 피드로 신규 업로드 자동 감지 가능 — 자동화 1순위 후보. 인스타는 API 부재+봇차단으로 수동 유지]

## 2-3. 소스 영상 확보 절차

1. 대상 상품 이미지 → 타오바오/알리 이미지 검색 → 중국어 제품명 확보
2. 중국어 제품명으로 더우인/샤오홍슈/콰이쇼우 검색
3. **복수 앵글 확보(필수):** 장점 강조 컷 / 문제 제기 컷(문제→해결 서사용) / 실사용 컷(생활감) / 얼굴 노출 컷(초반 후킹용) / 다양한 각도 — 편집 조립의 재료가 되므로 상품당 3~6개 소스 확보
4. 워터마크 없는 소스 우선
5. **AI 생성 영상 필터(필수):** 손동작·물리법칙 부자연 컷 = 제외. AI 생성물+허구 조합은 유튜브 정지 사유. 실촬영 소스만 통과
6. **유튜브 중복 체크(필수):** 상품명/유사 키워드로 유튜브 쇼츠 검색 → 동일 소스가 이미 한국 채널에서 사용됐으면 다른 앵글 소스로 교체. meta.json의 youtube_dup_checked에 기록 [AUTO: 검색 자동화 가능]

근거: 유튜브 재사용 판정 회피의 3중 방어 = ①유튜브에 없는 소스(중국 플랫폼) ②미사용 확인 ③완전 재가공(대본·더빙·편집 신규). 한국 크리에이터 콘텐츠 소싱은 저작권 신고 리스크(경고 3회=채널 삭제)로 금지.

# 3. 대본(스크립트) 생성 규격

## 3-1. 생성 로직

```
입력: 원본 영상 대본(추출) + 상품 정보(쿠팡 상세) + 채널 문체 프로필
처리: 스토리 구조·순서는 유지, 문장은 전면 재작성 (표절 회피 + 벤치마킹 효율)
출력: 채널별 문체가 적용된 신규 대본 + 후킹 3안
```
- 동일 원본을 N회 돌려도 N개의 서로 다른 대본이 나와야 함 (같은 상품을 채널 간·기간 간 재활용할 때의 전제)
- [AUTO: 클로드 코드로 대본 재생성 파이프라인 구축 — 원본 대본 추출은 STT, 재작성은 LLM 프롬프트 체인]

## 3-2. 대본 구조 템플릿 (검증된 서사 순서)

```
[0~2초] 후킹: 문제 제기 or 반전 결과 제시. 전체 편집 리소스의 30%를 여기에 투입.
        3안 생성 후 최강안 채택. (재학습/콜드 구간에선 테스트 노출당 시청지속률이 확산의 전부)
[본문]  문제 → 해결(제품 등장) → 사용 장면 → 구체적 장점 2~3개 (소스 컷과 1:1 매핑)
[말미]  가격/가성비 언급 → CTA
```

## 3-3. CTA 분기 (플랫폼별 상이 — 대본 생성 시 변수 처리)

| 플랫폼 | CTA 문구 방향 | 유입 경로 |
|---|---|---|
| YouTube (쇼핑태그 有) | "태그/제품 링크 확인" | 쇼핑태그 직결 (수수료 6~7%) |
| YouTube (태그 無) | "고정댓글/연결 영상 확인" | 고정댓글 링크 or 연결 롱폼 우회 |
| Instagram/Facebook | "○○ 댓글 남겨주세요" | 자동 DM(매니챗) — 멘트 최대 20종 분산(스팸 판정 회피) |
| TikTok/Naver Clip | "프로필 링크 확인" | 멀티링크(인포크링크류) |
| Threads | "댓글 유도" | 수동/반자동 |

## 3-4. 채널별 문체 프로필 (차별화 = 스팸 방어)

채널마다 다음 3요소를 고정 프리셋으로 분리: ①문체(존댓말 톤/구어체/정보형 등) ②TTS 보이스 ③자막 디자인 템플릿. 같은 상품을 다른 채널에서 다뤄도 소스·대본·보이스·자막이 전부 달라야 함.

# 4. 편집 규격

## 4-1. 컷 편집 원칙

- **무음 구간 제거:** 문장 사이 공백이 생기지 않도록 오디오와 클립을 겹쳐(overlap) 배치. 시청지속률 방어의 핵심 규칙
- 대본 문장 ↔ 소스 컷 1:1 매핑으로 조립 (대본이 편집 설계도 역할)
- 벤치마킹 원본 영상을 소스 폴더에 함께 보관 → 컷 순서 참고용
- 외국어 자막/텍스트 노출 구간: 잘라내기 > 확대(크롭으로 밀어내기) > 블러 순으로 처리
- 길이: 쇼츠 표준 30~60초. 후킹 2초 + 본문 + CTA 3~5초

## 4-2. 오디오

- TTS 어색함 보정: 원문 텍스트의 쉼표·마침표 위치 조정으로 호흡 제어 (문장 중간 마침표 삽입 = 끊어읽기 유도)
- BGM은 자주 쓰는 트랙을 채널별 풀로 확보해 재사용 (저작권 안전 트랙만)
- 인스타 배포분: 최근 유행 오디오 트랙 활용이 릴스 확산에 유리

## 4-3. 플랫폼 변형 출력

- 기본 완성본 + 무자막(클린) 버전 별도 저장: 클린 버전은 썸네일 제작용 + Threads용(무자막 영상이 반응 우위)
- 워터마크 절대 금지 (릴스 노출 감점 요인)
- CTA만 다른 2버전 출력: 댓글 유도형(인스타/페북) / 프로필·태그 유도형(유튜브/틱톡)

# 5. 업로드 규칙

## 5-1. 물량 한도

- 유튜브: 채널당 하루 2~3개, **3개 초과 금지** (알림 한도 3회 — 초과분 한계효용 급락 + 테스트 노출 상호 잠식)
- 단일 채널에 물량을 몰지 않음. 축소 운영 시 "1채널×6개"가 아니라 "2채널×3개"가 정답

## 5-2. 타이밍 규율 (타겟: 30~50대 여성)

| 슬롯 | 시간 | 근거 |
|---|---|---|
| 최우선 | 월요일 09:00~14:00 | 주말 미구매분 몰아서 구매 — 주간 매출 피크 |
| 평일 1차 | 09:00~11:00 | 주부 여유시간 |
| 평일 2차 | 18:00~20:00 | 퇴근 맞벌이층 |
| 주말 | 22:00~ | 일과 종료 후 시청 몰림 |

- **같은 시간대 고정 업로드** (알고리즘의 타겟층 학습 가속)
- 야간 제작 체제에서는 전량 예약 업로드로 슬롯 사수. 항상 3~5일치 재고(버퍼) 유지 — 제작과 유통의 분리 [AUTO: 멀티채널 예약 업로드 + 메타데이터 세팅 = 자동화 최우선 순위, 예상 절감 일 60~90분]

## 5-3. 메타데이터

- 제목/설명/해시태그/자막/영상 언어 = 전부 한국어 (채널 언어·국가 설정 포함)
- 고정댓글: 메인 링크 + "함께 쓰면 좋은 제품" 연관 링크 1~2개 (24시간 쿠키 매출 극대화 — 유입 1회당 발생 매출 상향) [AUTO: 고정댓글 일괄 세팅]

# 6. 알고리즘 메커니즘 (운영 판단의 근거 지식)

## 6-1. 플랫폼별 확산 특성

| 플랫폼 | 확산 창구 | 특성 |
|---|---|---|
| YouTube | 업로드 후 48시간 | 관심사 기반(구독자 비의존적). 채널 단위 카테고리 학습 후 폭발. 신규/피벗 채널은 약 2개월 학습 지연 구간 존재 |
| Instagram/Facebook | 1~3시간 골든타임 | 팔로워·소통 기반. 팔로워 수 ≈ 최소 고정 조회수 |
| TikTok | 24시간 서서히 | 단발 폭발보다 점진 확산 |
| Naver Clip | 3~4일 후 지연 폭발 | 신생 플랫폼 특성 |

## 6-2. 채널 재학습 (언어권 피벗 채널 전용 절차)

1. 신호 정화: 기존 타 언어권 영상 전량 비공개(YPP/쇼핑태그 자격은 비공개로 박탈되지 않음), 채널명·설명·배너·언어·국가 전면 한국화
2. 초반 물량 배분: 확산용(카테고리 내 트렌드 인접 포맷) 40% + 상품용 60% → 3주차 20% → 5주차 10%. 확산용도 반드시 **동일 카테고리 내**에서 (카테고리 이탈 = 학습 리셋)
3. 진도 지표(조회수보다 선행): 시청자 한국 비중(목표 70%+) → 재방문 시청자 증가 전환 → 시청지속률 우상향 → 조회수는 마지막에 움직임

## 6-3. 금지 행위와 근거

- 좋아요/댓글 상호 조작: 제재 이전에, 반응 계정의 성향이 학습 데이터로 들어가 타겟 매칭을 오염시켜 성장을 지연시킴
- 인위적 반복 멘트 자동 DM: 스팸 판정 → 멘트 분산(최대 20종)으로 회피
- AI 생성물 + 허구 서사 조합(유튜브): 정지 사유. 실촬영 소스는 서사가 허구여도 안전

# 9. 운영 체제 (병렬 블록 원칙)

근거: 뇌의 작업 전환 비용 — 같은 유형의 작업만 연속 처리하면 장시간에도 피로 누적이 적고, "완료 인식"이 생기지 않아 착수 저항이 없다. 상품 단위 완결(세로) 금지, 단계 단위 일괄(가로) 처리.

```
[블록 1] 소싱: 순찰 → 상품 확정 → 소스 확보/중복체크 → N건 일괄
[블록 2] 제작: 대본 N건 일괄 → TTS N건 일괄 → 편집 N건 일괄
[블록 3] 유통: 예약 업로드 + 메타데이터 + 고정댓글 N건 일괄
[블록 4] 측정: KPI 5분 (국가 비중 → 재방문 → 사다리)
```

위임 시: 블록 1 후반(소스 다운로드)~블록 2를 프리랜서에게, 블록 1 전반(전략)·블록 3(계정 접근)·블록 4(데이터)는 운영자 전담. 운영 시트만으로 작업 가능하게 하고 계정 정보는 마스터에만 존재.

성숙 단계 참고 모델(외부 사례): 콘텐츠를 재고 200개 수준으로 선제작해 쌓고, 업로더(주 3일·4시간·월 30~40만)는 배분만 담당. 인센티브(실수익 3~5%)로 업로드 품질 정렬. 단 대량 선제작은 **승리 패턴 검증 이후**에만 유효 — 검증 전 대량 재고는 틀린 콘텐츠의 재고화. 재고화 대상은 에버그린(상품용)만, 트렌드 확산용은 즉시 제작·소진.
