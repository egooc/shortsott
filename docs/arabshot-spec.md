# 어랍숏 제작 규격 (인수인계본)

2026-09-22 기준. 레퍼런스 채널 **@urabshorts** 60편 실측 + 실제 제작 19편에서 나온 규칙 전부.
이 문서 하나로 한 편을 처음부터 끝까지 만들 수 있게 썼다.

---

## 0. 한 편이 어떻게 생겼나

| 항목 | 값 | 근거 |
|---|---|---|
| 길이 | **30~35초** (원본 소스는 25~90초) | 실제 완성본 7편 전부 30.2~34.8초 |
| 화면 | 1080×1920 · 30fps | 채널 규격 |
| 구조 | **콜드 오픈 1.6초 → N/D 번갈이 13컷** | 사례 76 |
| 내레이션 | 9문장 · 평균 **28~31자** | 레퍼런스 실측 31.7자 |
| 화면 자막(D컷) | 4장 · 각 1초 | — |
| 효과 문구 | 4~5개 · 보라색 · y=1060 | — |
| 자막 | 흰색 · y=1250 · 카드당 **11자 이하** | 폭 제한 |
| 현장음 | 전 구간 · 내레이션 아래 **−6dB** | 사례 68 |
| 실비 | **TTS 1회.** ASR 0원 | 사례 60 |

**핵심 한 줄**: 어랍숏은 편집 기술이 아니라 **원고**다. 같은 소스로 원고만 바꿔 두 번 만들어 봤는데
완전히 다른 물건이 됐다(arab17 → arab21).

## 1. 소재 — 세 개의 문을 다 통과해야 한다

### 1-1. 기계 기준 (정찰기가 자동으로 거른다)
- 길이 **25~90초**
- 오디오 평균 **−45dB 초과** (무음이면 어랍숏이 성립하지 않는다)
- 긴 변 **1280 이상** (이하는 1080×1920 으로 올릴 때 뭉개진다)

★레딧은 **무음 AAC 트랙**을 붙여 내보낸다. 형식 목록에 `audio only` 가 보여도 판정이 안 된다.
**음원만 받아 실제로 재야 한다**(사례 65).

### 1-2. 욕구 축 — 하나에 명확히 걸리지 않으면 버린다 (사례 71)

| 축 | 레퍼런스 근거 | 안전하게 가는 법 |
|---|---|---|
| 고통·신체 | 클라이머 연고 200만 · 코 푸는 법 38만 | 상처·수술 금지. 해결·요령 쪽으로 |
| 먹기·경쟁 | 식탐 친구 66만 · 오만 치킨 12만 | 먹방 아닌 «뺏김·양·속도»의 긴장 |
| 공포·긴장 | 환공포증 집 46만 | 유혈·시신 금지. 시각적 불편함까지만 |
| 돈·격차 | 두바이 부자 6.5만 | 비난 아닌 구경 |
| 사회적 마찰 | 답정너 34만 · 핸드폰 잔소리 29만 | 특정인 조롱·싸움 금지 |
| 낯선 곳의 일상 | 인도 담배 28만 · 일본 관광 20만 | 국가·민족 비하 금지 |
| 규모·불가능 | 나무집vs벽돌집 190만 | — |

**솜씨 구경은 예쁘지만 끌어당기지 않는다.** 도마뱀이 달걀 먹고 모래를 깎는 편이 그래서 심심했다.
챌린지·뻔한 공감·AI 생성물은 레퍼런스 바닥권이다.

### 1-3. 유튜브 정책 — 소재 단계에서 뺀다
유혈·부상·시신 · 싸움·괴롭힘 · 성적 내용 · **따라 할 위험이 있는 행동** · 정치·종교·젠더 논쟁.
조회수가 나와도 광고가 안 붙고 신고를 부른다.

> 실제로 버린 것: 커튼 타고 오르는 아이(미성년자+모방 위험) · 달아난 말(미성년자+위험한 동물) ·
> 전 배우자 관련 사건(폭력) · ICE 관련(정치)

**자극은 소재가 아니라 프레임에서 만든다.** → §3, §4

### 1-4. 번인 확인 — 여기서 제일 많이 버린다
- 앞뒤 제목 카드·영어 자막의 사라지는 시각을 **0.1초 단위로** 잰다(사례 61).
- **화면 안에서 위치가 움직이는 번인 오버레이는 버린다.** 가릴 방법이 없다(사례 67).
- **예외: 원작자 계정 표기(작은 워터마크)는 지우지 않고 그대로 둔다.** 크레딧에 함께 적는다.
  사례 67 의 '움직이는 번인'은 남의 영상처럼 보이게 만드는 큰 제목 카드를 말한 것이다.

빠른 확인법: 1초 간격 컨택트 시트 한 장이면 거의 다 걸러진다.
```
ffmpeg -i src.mp4 -vf "fps=1,scale=210:-1,tile=6x4" -frames:v 1 sheet.jpg
```

### 1-5. 소스 경로
현재 **레딧**을 쓴다. 틱톡은 IP 차단, 인스타는 로그인 세션이 필요하다(사례 64).
레딧은 비로그인 `top.rss` 가 200 으로 돌고, **피드 순서가 곧 바이럴 순위**다.

지금 쓰는 판(정찰기 기본값):
```

Damnthatsinteresting · interestingasfuck · nonononoyes
blackmagicfuckery · Wellthatsucks
```
★`oddlyterrifying`·`mildlyinfuriating` 은 **사진 게시물이 대부분**이라 뺐다(실측).

**권리**: 출처 표기 기준이다(소유주 결정 2026-09-19). `rights.basis = credit_only`,
하단 크레딧에 `via r/<서브레딧>`. 레딧은 재게시가 많아 게시자와 원작자가 다를 수 있다 —
원작자를 알면 credit 을 고친다.

## 2. 소스 손질 — 콜드 오픈을 만든다 (사례 76)

어랍숏 소재는 대개 «평범 → 점점 → 대박» 순서다. 그대로 쓰면 **첫 3초가 가장 심심하다.**

**결말(또는 가장 센 그림)을 잘라 원본 앞에 1.6초 붙이고 재인코딩한다.**

```
ffmpeg -ss <센 구간> -t 1.6 -i src.mp4 -vf "scale=1080:1920:flags=lanczos,fps=30" \
       -c:v libx264 -crf 18 -preset medium -c:a aac -b:a 128k -ar 48000 hook.mp4
ffmpeg -i src.mp4 -vf "scale=1080:1920:flags=lanczos,fps=30" \
       -c:v libx264 -crf 18 -preset medium -c:a aac -b:a 128k -ar 48000 body.mp4
printf "file 'hook.mp4'\nfile 'body.mp4'\n" > cc.txt
ffmpeg -f concat -safe 0 -i cc.txt -c:v libx264 -crf 18 -preset medium \
       -c:a aac -b:a 128k -ar 48000 -movflags +faststart volcano_src.mp4
```

- ★**반드시 재인코딩.** `-c copy` concat 은 타임스탬프가 어긋나 엔진이 프레임을 잃는다(사례 67).
- 엔진은 이어 붙인 지점을 **샷 경계로 정확히 잡는다**(실측). 첫 내레이션이 그 경계를 넘어 이어지므로
  **말은 안 끊기고 그림만 바뀐다.**
- 지루한 중간 구간을 잘라내도 된다 — **결정적 그림을 마지막 문장 밑으로 당기는 데 쓴다**(사례 79).
- 원본 소리는 **살린다**. 어랍숏의 알맹이다.

## 3. 제목 — 자극은 여기서 만든다 (사례 71)

레퍼런스 실측: **상위 20편 중 10편이 아래 틀을 쓴다. 하위 15편은 2편뿐이다.**

| 틀 | 레퍼런스 | 쓰는 법 |
|---|---|---|
| **전언형** `~라는/~한다는` | 클라이머들이 **쓴다는** 개발바닥 연고(200만) | 내부자만 아는 것처럼 |
| **대결형** `A vs B, 어느 게` | 나무집 **vs** 벽돌집, **어느 게 더 좋을까**(190만) | 답을 마지막에 |
| **질문형** `~까` | 모래로 어디**까**지 만들 수 있을**까** | 마지막 장면이 답해야 한다 |
| **극단 부정** `절대 ~못/~없는` | 환공포증 환자는 **절대 살 수 없는** 집(46만) | 누가 못 견디는지 지목 |
| **이유 약속** `~한 이유` | 흑인이 N단어를 독점하게 **된 이유**(89만) | 이유를 실제로 보여줘야 한다 |
| **과장 규범** `이 정도는` | 남자가 코 풀 때 **이 정도는 해야지**(38만) | 과장인 게 보이게 |

두 줄 모두 짧게(각 **9자 안팎**). 같은 글자 크기라 한 줄만 줄일 수 없다.
★**약속한 것을 마지막 장면이 반드시 보여줘야 한다.** 못 보여줄 약속은 낚시고, 정책 위반이며 이탈을 부른다.

> 실제 예 — "절대 젓지 말라는 / 통 속 검은 물"(극단 부정) · "차가 와도 절대 / 안 비키는 비버"(극단 부정) ·
> "파도가 덮쳐도 / 한 발도 안 뺀다"(극단 부정)

## 4. 원고 — 여기가 어랍숏의 전부다

세 층이 쌓인다. **아래로 갈수록 나중에 배운 것이고, 위층만으로는 재미가 안 난다.**

### 4-1. 꼴 (사례 68)
- **한 문장 평균 31.7자.** 토막을 쓰면 어랍숏이 안 된다.
- **대상을 이름으로 부르고 시작** — "갯가재라는 생물은 사냥을 할 때면"
- **연결어로 문장을 겹친다** — "이처럼", "제아무리 ~해도", "심지어", "결국", "그러거나 말거나"
- **끝에 화자의 평** — "이 정도면 거의 깡패나 다름없네요"
- 한 문장이 카드 여러 장에 걸쳐 흐른다. **카드 하나 = 문장 하나가 아니다.**
- 카드는 공백 포함 **11자 이하**(BMDOHYEON 107pt 기준).

### 4-2. 말맛 — 대상을 «캐릭터»로 다뤄라 (사례 77)
길이만 맞추면 **설명문 9줄**이 된다. 레퍼런스와의 차이는 길이가 아니라 **화자의 태도**였다.

| 장치 | 레퍼런스 | 쓰는 법 |
|---|---|---|
| **의인화** | "웬만한 것들은 **그의** 상대가 안 되는데요" | 사물도 «놈»으로 부른다. 돌변한다·부아를 낸다·덩치를 불린다 |
| **비유** | "치고 빠지는 게 완전 **복서 스타일**이고" | 일상 사물·직업에 빗댄다. 한 편에 하나면 충분 |
| **딴지·감탄** | "**살려주시옵소서**" | 화면 자막(D컷)이 이 역할 — "선을 넘네", "누가 좀 말려" |
| **끝 한마디** | "이 정도면 거의 **깡패나 다름없네요**" | 제목과 호응시켜 닫는다 |

**자가 점검**: 아홉 문장이 전부 «~합니다/~있습니다»로 끝나고 **주어가 전부 사물**이면 다시 써라.

```
전: 검고 매끈하던 표면이 점점 잿빛으로 일어나는데요
후: 검고 매끈하던 게 슬슬 잿빛으로 부아를 내는데요
```

### 4-3. 긴장 설계 — 7축을 «극단으로» 끌고 간다 (사례 79)

> 소유주: "긴박하지 않아도 긴박하게, 위험하지 않아도 위험한 것처럼, 놀랍지 않아도 놀라운 것처럼
> 원고를 만들어 주고 상황을 끌고 가고 묘사해 줘야 재밌어지는 것이다."

7축은 **후보를 거르는 체**일 뿐이다. 비버가 길 건너는 건 그냥 길 건너는 것이고, 그걸 «대치»로
만드는 건 문장이다.

| 장치 | 안 쓴 문장 | 쓴 문장 |
|---|---|---|
| **판돈 선언** | "비버가 차선을 건넙니다" | "**1톤짜리 픽업 앞에서** 비버가 차선을 건넙니다" |
| **가정법 최악** | "트럭이 멈췄습니다" | "**한 발만 늦었어도** 하는 순간이었는데요" |
| **시간 압박** | "천천히 끌고 갑니다" | "**그 사이에도** 뒤에서는 계속 기다리는데요" |
| **단위 과장** | "긴 나뭇가지" | "**제 몸통 두 배는 되는** 나뭇가지" |
| **보류** | (바로 설명) | "**문제는 여기서부터인데요**" |
| **반문** | "대단합니다" | "**이걸 보고도** 경적을 울릴 수 있을까요" |
| **서열 선언** | "무사히 건넜습니다" | "**결국 이긴 쪽은** 비버였습니다" |

**사다리로 쌓는다.** 아홉 문장이 평평하면 안 된다:
`상황 → 판돈 → 압박 → 최악의 가정 → 반전 → 판정`

### 4-4. ★거짓말 금지선
- **되는 것**: 가정법("~했을 자리인데요") · 비교("~두 배") · 판정("이긴 쪽은") · 반문 · 보류.
  전부 **화면에 있는 것만** 가지고 만든다.
- **안 되는 것**: 화면에 없는 사건을 단정 · 없는 숫자 · 없는 소리.
- **판별법 한 줄**: **그 문장이 틀렸다고 지적당했을 때 화면을 가리키며 방어할 수 있는가.**
  가정법은 방어된다("그랬다면"이라고 했으니까). 단정은 방어되지 않는다.

### 4-5. 자막은 화면에 있는 것만 말한다 — 어긋나는 두 방식
1. **없는 걸 말한다**(사례 62): "Octopus Getaway" 를 믿고 '도망간다'고 썼는데 문어는 그냥 헤엄쳤다.
   → **원본 제목을 근거로 쓰지 마라.** 크롭 밖은 없는 것이다.
2. **있는데 그때 안 보인다**(사례 72·78): 카메라가 밀고 들어가거나, 그 물건이 이미 화면을 떠났다.
   → **그 카드가 뜨는 프레임 번호**를 뽑아 확인한다.

★**그래서 원고를 쓰기 전에 «무엇이 몇 초까지 화면에 있는지»를 먼저 재라.**
이 확인 한 번이 TTS 한 번과 왕복 예닐곱 번을 아낀다.

고치는 순서(싼 것부터):
1. **컷 순서를 바꾼다** — D컷을 그 문장 뒤로 옮긴다 (공짜)
2. **소스를 자른다** — 지루한 구간을 들어내 결정적 그림을 당긴다 (공짜)
3. **원고를 고친다** — TTS 를 새로 산다. **게다가 음성을 이미 산 폴더에서는 못 바꾼다**
   (`paid_request_uncertain`). 소스 mp4 와 자막 vtt 만 복사해 **새 작업 폴더**를 판다.

## 5. 자막 파일 — 실비 0원의 비결 (사례 60)

원본과 **같은 basename** 으로 `volcano_src.vtt` 를 두면 엔진이 ASR 을 부르지 않는다
(`timing_kind: cue`). 12큐 안팎, 각 **11자 이하**.

```
WEBVTT

1
00:00:00.700 --> 00:00:01.500
길을 막았다
...
```

내용은 화면에서 일어나는 일을 짧게 적으면 된다 — 정확한 전사일 필요가 없다.

## 6. 편집표 — 끊기는 자리를 만들지 마라

- **현장음만 나오는 빈 구간을 두지 않는다.** 내레이션(N)을 등끼리 붙이고 사이에 **1초짜리 화면 자막(D)** 만 끼운다.
- 목표 밀도: **0.7초마다 글자가 바뀐다.** 35초 기준 내레이션 카드 40장 안팎 · 화면 자막 4~5장 · 리액션 4~5개.
- 배치: `N N D N N D N N N D N D N` (13컷)
- 리액션 문구는 `position: [540, 1060]`. 자막이 y=1250 이라 190px 띄워야 겹치지 않는다.
- 효과음은 pop·bonk·ding 중 **실제 동작이 있는 자리에만**. 수를 맞추려고 채우지 마라.

### 6-1. 컷 시각 맞추기 — 실무 다섯 줄
1. ★**0번 프레임에서 시작하지 마라.** 정밀 디코드가 한 장을 잃는다. 첫 컷은 **f18**(사례 67).
2. 그림 프레임 ≈ `round((발화초 + 0.168) × 30)`. TTS 응답 `paid/*/response.json` 의 `words` 를
   내레이션 토큰 수만큼 끊어 읽으면 나온다. **실측과 정확히 맞는다.**
3. 1차 제출은 **컷마다 여유를 6~12프레임 주고** 던진다. 그러면 `invalid`(한 건만 알려 줌) 대신
   `edit_required` 로 떨어져 **전 컷의 실측 끝 프레임을 한 번에** 받는다.
4. 받은 실측으로 **빈틈 없이 이어 붙여** 재제출한다. `same_shot_source_gap` 이 0이 되면 통과한다.
5. ★**시각을 소수 6자리로 적어라.** 3자리로 자르면 `715/30 = 23.833` 이 되돌아갈 때 **714** 가 되어
   한 프레임이 사라진다.

★D컷 창 크기는 자리마다 다르다(29~37프레임). 보고서의 실측에 맞춘다.
★컷이 **샷 경계를 걸치면** 15프레임 미만 조각이 남아 반려된다. 경계에 딱 맞춘다 — 이걸 이용해
**마지막 문장을 결정적 샷의 첫 프레임에 앉힐 수 있다.**
