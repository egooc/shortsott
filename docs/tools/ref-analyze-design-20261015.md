# ref-analyze 설계안 v0 (도구개발, 2026-10-15) — 관리자 검토용, A 공유 전

백로그 2(분석 4종 + 분류)의 1단계 = ref-9dim. 이 문서는 **열 이름과 정의를 먼저 고정**하려는 것이다. 열이 정해지면 코퍼스를 쌓기 시작하고, 2단계(편집 스타일·업로드 패턴 확장)는 같은 표에 열을 더하는 식으로만 간다(기존 열 이름·뜻은 바꾸지 않는다).

## 1. 결론부터 — longform_competition 확장이 아니라 별도 도구로

| | longform_competition.py | ref-analyze |
|---|---|---|
| 묻는 것 | 이 에셋 쇼츠를 «남이 몇 채널이나» 올리나(수요×공급) | 이 채널 편들이 «어떻게 생겼나»(원고·편집·제목) |
| 입력 | 검색어 | 채널 핸들 하나 → 그 채널 편 20~100개 |
| 비용 | innertube 검색만, 0원 | 편 목록·메타 0원 + 전사(유료) + 영상 내려받기(CPU) |

입력도 산출도 겹치지 않아서 확장하면 한 파일에 두 도구가 산다. A의 파일은 고치지 않고, 쓸 만한 부분(innertube·oEmbed)은 import만 한다.
제안 경로: `scripts/ref_analyze.py`(새 파일), 결과 `D:/midform/reference/<lane>/<channel>/`.

## 2. 흐름 (1단계)

1. **편 목록**: `yt-dlp --flat-playlist https://www.youtube.com/@<핸들>/shorts` → 최근 N편(기본 40, 하한 20). 0원.
2. **편 메타**: `yt-dlp -j` 편마다 → 조회·좋아요·댓글·업로드일·길이·제목·설명·태그. 0원.
3. **조회수군**: 채널 안에서 조회수 순위 → 상위 30% = `top`, 하위 30% = `bottom`, 나머지 `mid`. 업로드 7일 미만은 조회가 덜 쌓였으니 `young`으로 빼고 군에 넣지 않는다.
4. **전사**: `rinbox_transcribe.py`(Speechmatics, 채택 도구) import. 20편×45초 ≈ 15분 분량. vidIQ transcript가 있으면 그쪽을 먼저 쓴다(0원).
5. **영상**: 360p로 받아 장면 전환(ffmpeg scene, 문턱은 rinbox_screen과 같은 0.12)·첫 3초 소리 크기. 정치 렌더 창(18:30~00:30)에는 돌리지 않는다.
6. **측정 → 표**: 아래 3장의 열을 편마다 한 줄씩 → `dims.csv` + 군별 중앙값과 차이 `summary.json`.

## 3. 열 (고정 제안) — 편 한 줄 = 한 영상

식별·메타 (측정이 아니라 바탕):

| 열 | 뜻 |
|---|---|
| `video_id` · `channel` · `lane` | |
| `title` · `published` · `duration_s` | |
| `views` · `likes` · `comments` · `views_per_day` | `views_per_day` = views / 업로드 뒤 일수 |
| `group` | top / mid / bottom / young |
| `speech_share` | 전사 낱말이 덮는 시간 / 길이 (말 비중 — 해설형인지 원음형인지 가른다) |

9차원 (ref-9dim):

| # | 열 | 정의 | 재는 법 |
|---|---|---|---|
| 1 | `sent_len_avg` | 문장 평균 글자 수(공백 뺌) | 전사를 문장으로 자름(ko: 다·요·까·죠·! ? . / ja: 。！？) |
| 2 | `end_da` `end_yo` `end_q` `end_noun` `end_etc` (ja: `end_desu` `end_da` `end_q` `end_noun` `end_etc`) | 종결 유형 비율, 합 1.0 | 문장 끝 형태 규칙 |
| 3 | `hook_idx` | 처음 «후킹 문장»이 몇 번째 문장인가(1부터, 없으면 0) | 질문·숫자·반전 표지(근데·사실·알고 보니 / 実は·でも) 중 하나가 든 첫 문장 |
| 4 | `ending_type` | 엔딩 유형 하나 | gpt-ask 라벨, 고정 목록: `reveal`(반전) · `punchline`(닫는 한 줄) · `question`(질문) · `cta`(구독·원작 유도) · `open`(안 닫음) · `cut`(말 없이 끊김) |
| 5 | `title_len` | 제목 글자 수(해시태그·#shorts 뺌) | |
| 6 | `title_num` | 제목에 숫자 있음 0/1 | |
| 7 | `title_bang` | 제목에 ! 또는 ? 있음 0/1 (`!`·`?` 따로 세려면 2단계) | |
| 8 | `cut_len_avg` | 평균 컷 길이(초) = 길이 / (장면 전환 수 + 1) | ffmpeg scene 0.12 |
| 9 | `kill_s` | 첫 3초 안의 «센 순간» 시각(초), 없으면 null | 0~3초 중 장면 전환 또는 소리 크기 최대점 중 이른 쪽. E1(킬샷 0~3초) 판정은 `kill_s ≤ 3` |

`summary.json`: 열마다 top·bottom 중앙값(비율 열은 평균), 차이, 표본 수. **군당 6편 미만이면 차이를 내지 않고 «표본 부족»으로 적는다**(책 06 하한 20편 × 30%).

## 4. 2단계에서 붙일 것 (열 이름만 예약)

- 편집 스타일: `frame_type`(세로 크롭/16:9 창/머리띠) · `cap_chars_avg`(박힌 자막 글자 수, OCR) · `cap_pos` · `bgm` 0/1 · `end_card` 0/1
- 원고: `emo_share`(감정 문장 비율 — emotion-label 도구가 생기면 그 값) · `structure`(기승전결/3중 반복)
- 업로드: `pub_weekday` · `pub_hour`(KST) · `tags_n` · `desc_template` 해시
- 채널 표(편이 아니라 채널 한 줄): 개설일·구독·총 조회·주당 편수·시리즈 수·중앙값·3배 튀는 편 수·댓글비·복제형 여부(S13)·권리자 유형
- 분류 한 장(`classify.md`): 포맷 유형 / 가까운 우리 레인 / 따라가려면 바꿀 3칸 / 필요한 도구

## 5. 회귀

- 통과해야 할 것 3: 열 계산 단위 테스트(문장 자르기 ko·ja, 종결 비율 합 1.0, 제목 해시태그 제외).
- 걸려야 할 것 3: 표본 19편이면 «표본 부족», 군 6편 미만이면 차이 없음, 7일 미만 편은 군에서 빠짐.
- 실측 대조 1: 이미 손으로 잰 값과 맞춘다 — 메모리 «레퍼런스 채널 실측»(해설 72%·6.5문장/분 vs 31%)을 같은 채널로 다시 재서 `speech_share`가 ±5%p 안인지.

## 6. 첫 표본과 비용

- C ja 벤치 20편 — **어느 채널이 벤치인지 C가 정해 줘야 한다**(東映時代劇YouTube는 소스이지 벤치가 아니다).
- 도구의쓸모 대체 후보 — 발굴 카드의 대장간·공정 상위 채널 중 원작자형 1곳 + 양산형 1곳(tag-share 실측의 16채널 중 하나)을 대조용으로.
- 비용: 메타 0원, 전사 40편×45초 ≈ 30분 분량(Speechmatics), gpt-ask 라벨 40건(구독 안). CPU는 360p 장면 검출이라 가볍지만 렌더 창 밖에서.

## 7. 정해 줄 것 (관리자 → A·C)

1. 별도 도구(`scripts/ref_analyze.py`)로 가는 데 A 동의.
2. 9차원 정의 중 A가 이미 다르게 쓰는 값이 있는지(특히 `hook_idx`·`kill_s`). 있으면 A 정의를 따른다.
3. C ja 벤치 채널 이름.
4. 전사 비용 승인 범위(첫 표본 40편).
