# dup-frame 설계안 v0 (도구개발, 2026-10-15) — 쇼핑 요청, 관리자 검토용

쇼핑 회신: 제목 겹침으로는 «같은 더우인 클립을 다른 한국 채널이 이미 올렸나»를 못 잡는다(«무타공 청소도구 걸이» 남의 최고 145만인데 제목이 달라 PASS). → **그림으로 맞댄다.** dup-check와는 별도 도구이고, dup-check `--info`가 뽑은 10만+ 편을 입력으로 받는다.

## 1. 하는 일

우리 소스 클립(더우인 등에서 받은 원본) ↔ 검색 상위 쇼츠(dup-check `--info` 결과의 10만+ 편, 기본 상위 10편)를 프레임 해시로 맞대어 «같은 원본에서 나온 편»을 찾는다.

```
node scripts/dup-check.js --lane ko "무타공 청소도구 걸이" --info --json > cand.json
python scripts/dup_frame.py --ours D:/volcano-runs/ffshopNN/source.mp4 --cand cand.json [--top 10] [--sheet]
```

## 2. 방법

1. **우리 쪽**: 소스에서 장면 전환마다 1장 + 2초 간격 샘플(최대 60장). 가운데 정사각형 창도 따로 해시한다(쇼핑은 정사각형 창으로 중국어 띠를 지우니 남도 크롭·띠를 붙였을 수 있다).
2. **남의 쪽**: 후보 쇼츠마다 썸네일(`i.ytimg.com/vi/<id>/oar2.jpg`, 0원) + 360p 앞 15초를 받아 1초 간격 15장. 영상 받기가 막히면 썸네일만으로 판정하고 «썸네일만»이라고 적는다.
3. **해시**: OpenCV(이미 설치 5.0, 새 패키지 없음)로 dHash 64비트 + 색 히스토그램. 남의 편은 자막 띠·머리띠가 붙으니 **위아래 20%를 자른 가운데**와 **전체** 두 가지를 다 해시한다.
4. **매칭**: 프레임 쌍 해밍 거리 ≤ 10이면 «닮음». 남의 편 프레임 중 닮은 프레임이 3장 이상이면서 우리 소스의 서로 다른 장면 2곳 이상에 걸리면 `SAME_SOURCE`, 1~2장이면 `MAYBE`, 0장이면 `CLEAR`.
5. **눈 검사 시트(--sheet)**: `MAYBE`·`SAME_SOURCE` 편마다 «우리 프레임 | 남의 프레임» 짝 4개를 한 장에 붙여 PNG로 둔다. 최종 판정은 눈(박힌 자막 검사와 같은 원칙).

## 3. 산출

- 편마다 `{id, views, handle, verdict, matched_frames, our_scenes_hit, best_distance, thumb_only}` → `dup_frame.json`
- 쇼핑 `_gate_log.jsonl` 형식으로 한 줄(kind `dup_frame_same` / `dup_frame_maybe`).
- 종료 코드: 0 CLEAR만 · 4 SAME_SOURCE 하나 이상 · 5 MAYBE만.

## 4. 회귀 (만들 때)

- 걸려야 할 것 3: 우리 소스를 ① 9:16 크롭 + 위아래 자막 띠, ② 좌우 반전 없이 1.1배 확대 + 밝기 +10%, ③ 앞 3초를 잘라 낸 판 — 셋 다 SAME_SOURCE.
- 통과해야 할 것 3: 같은 제품의 다른 촬영(쇼핑 지난 작업 폴더의 다른 소스 2개), 같은 욕실 배경의 다른 제품, 무관 쇼츠 — CLEAR.
- 실측 1: «무타공 청소도구 걸이» 145만(@salrim_jam)과 그 편의 소스가 쇼핑 폴더에 있으면 맞대 본다.

## 5. 비용·제약

- 0원(썸네일·360p 15초). 후보 10편 × 15초 내려받기. CPU 가벼움, 그래도 정치 렌더 창(18:30~00:30)·10-16 07:40~08:30 드라이버 업데이트에는 돌리지 않는다.
- 좌우 반전은 1판에서 안 본다(필요하면 반전 해시를 하나 더). 재편집으로 원본 장면을 30% 넘게 가린 편은 놓칠 수 있다 → «CLEAR = 같은 원본 없음»이 아니라 «못 찾음»으로 적는다.
- 쇼핑 코드(shop_*·ff_render)는 안 건드린다. 새 파일 `scripts/dup_frame.py`만.

## 6. 정해 줄 것

1. 쇼핑: 입력 소스 경로 규칙(작업 폴더 어디에 원본이 있나), 후보 상위 몇 편까지 볼지(기본 10).
2. 우선순위: ref-analyze 1단계와 어느 쪽 먼저인지(제안: ref-analyze 설계 합의를 기다리는 동안 dup-frame을 먼저 만든다).
