# 일본 정치 公式 소재 수집기 — 설계안 (도구개발, 2026-10-16)

상태: **설계안만.** 구현은 발굴 세션이 소재 풀(어느 진영·어느 채널·어느 회의)을 정한 뒤에 한다.
관리자 큐(10-15): «公式 소재 수집기 설계안만(国会 인터넷 심의 중계 衆参·정당·정치인 채널, yt-dlp, 발언자·시각·회의명 메타)».
배경: 일본 정치 롱폼 시험(소유주 10-15 «진행»). 쟁점브리핑 틀을 그대로 쓰되 별도 세션·채널로 간다. 소재는 国会와 정당의 공식 영상이다.

## 1. 무엇을 모으나

| 소재 | 출처 | 받는 길 | 확인 |
|---|---|---|---|
| 국회 영상(衆) | 衆議院インターネット審議中継 shugiintv.go.jp | yt-dlp `ShugiinItvVod`·`ShugiinItvLive` | 추출기 있음(yt-dlp 2026.08.19 목록). 실제 받기는 첫 구현 때 시험 |
| 국회 영상(参) | 参議院インターネット審議中継 webtv.sangiin.go.jp | yt-dlp `Sangiin` | 위와 같음 |
| **발언 원문·발언자** | 国会会議録検索システム API kokkai.ndl.go.jp/api/speech | HTTP GET(JSON, 키 없음) | **10-16 실호출 확인.** speaker·speakerGroup(会派)·speakerPosition·nameOfHouse·nameOfMeeting·issue·date·speechOrder·speech·speechURL. 10-09 예산위원회 회의록이 10-16에 이미 올라와 있다(약 1주 지연) |
| 정당·정치인 채널 | 각 당 공식 유튜브(자민당·立憲·維新·国民·公明·共産·れいわ·参政 등)와 의원 개인 채널 | yt-dlp 채널 목록·메타 | 채널 목록은 발굴 세션이 정한다(진영 결정과 묶임) |
| 기자회견 | 首相官邸·각 당 회견 | 위 정당 채널, 官邸 유튜브 | 발굴 몫 |

**핵심: 영상과 발언 원문을 회의록 API로 짝짓는다.** 영상만으로는 «누가·몇 시에·무엇을» 말했는지 전사(유료)를 해야 안다.
회의록 API가 발언자·순서·원문을 공짜로 준다. 영상 쪽은 «어느 구간이 그 발언인가»만 찾으면 된다.

## 2. 흐름

```
① 회의 목록     회의록 API(date·nameOfHouse·nameOfMeeting) + 중계 사이트 VOD 목록 → 회의 단위 meeting.json
② 발언 표       회의록 API speechRecord 전부 → speeches.jsonl (speaker·会派·직책·순서·원문·speechURL)
③ 영상 메타     yt-dlp --dump-json --skip-download (VOD 길이·시작 시각·제목) → video.json
④ 구간 정렬     영상의 필요한 구간만 받아 ASR(Speechmatics, 구간만 보내 돈을 아낀다 — rinbox_transcribe --from/--to)
                → 회의록 원문과 글자 정렬(rinbox_reuse.text_index 방식) → 발언마다 영상 시작·끝 초
⑤ 소재 카드     발언 하나 = 카드 하나: {회의명, 날짜, 발언자, 会派, 직책, 원문, 영상 URL, 시작·끝 초, 회의록 URL}
```

- ①~③은 돈이 0원이다. 하루 회의 수십 건 메타를 다 모아도 디스크는 수 MB다.
- ④부터 돈과 디스크를 쓴다. **원고에 쓰기로 고른 발언만** 받는다. 회의 전체를 받지 않는다(衆 예산위원회 하루분이 7시간 안팎).
- 회의록은 약 1주 늦게 올라온다. 당일 소재는 회의록 없이 ASR만으로 가야 한다 → 그날 편은 «발언자 확인 필요» 표시를 달고, 회의록이 올라오면 다시 대조한다.

## 3. 저장 형식

```
D:/midform/ja-politics/sources/<YYYYMMDD>_<house>_<meeting>/
  meeting.json     {"house","meeting","issue","date","session","video_urls":[...],"minutes_url"}
  speeches.jsonl   한 줄에 발언 하나 — 회의록 API 필드 그대로 + "video_t0","video_t1"(정렬 뒤)
  video.json       yt-dlp 메타(받은 구간 목록 포함)
  clips/           고른 구간 mp4(원고에 쓰는 것만)
```
- 저장 위치는 정치 ja 세션이 정한다(위는 예시). 영상은 디스크를 쓰니 D: 여유 20GB 규칙을 따른다.
- 원고(③ ja 정치 원고 틀)는 카드의 `speechURL`을 출처 칸에 그대로 쓴다 → «출처 URL 필수» 규칙을 자동으로 채운다.

## 4. 권리·규칙 (구현 전에 확인할 것)

- 일본 저작권법 제40조 1항: 공개된 정치 연설·국회 진술은 원칙적으로 자유롭게 이용할 수 있다. 다만 **발언 내용**에 대한 조항이다. **중계 영상 자체**의 이용 조건은 衆·参 사이트의 이용 안내를 따로 확인해야 한다 → 구현 착수 전에 gpt-ask로 원문 확인 후 rights.basis에 적는다.
- 정당·의원 유튜브는 각 채널 영상이라 일반 클립 규칙(출처 표기·rights.basis 기록)을 따른다. 소유주 결정(소셜 소스는 막지 말고 기록)과 같은 결이다.
- 명예훼손 대비: 카드에 원문과 회의록 URL이 붙어 있어야 원고 틀의 «진실성» 검사(④ 원고 틀)를 기계로 걸 수 있다. 카드가 없는 발언 인용은 원고 단계에서 막는다.
- 429/403이 나면 멈춘다. 우회하지 않는다. 회의록 API는 공개 API이니 요청 간격을 둔다(1초 이상, 한 번에 maximumRecords ≤ 100).

## 5. 구현 단위(승인 뒤)

1. `scripts/ja_kokkai_minutes.py` — 회의록 API 수집(날짜·회의·발언자 필터) → speeches.jsonl. 오프라인 픽스처 테스트.
2. `scripts/ja_kokkai_video.py` — 중계 VOD 메타·구간 받기(yt-dlp 래퍼). 실제 받기 시험 1건으로 추출기 동작부터 확인.
3. `scripts/ja_kokkai_align.py` — 구간 ASR ↔ 회의록 원문 정렬 → video_t0/t1.
4. 소재 카드 출력은 발굴 세션 카드 형식에 맞춘다(발굴이 형식을 주면).

## 6. 정할 것(소유주·발굴)

- 진영과 채널 목록(발굴 카드를 보고 소유주가 정함). 진영이 정해져야 정당 채널 범위가 정해진다.
- 국회 영상을 주 소재로 쓸지, 정당·토크 채널을 주로 쓸지. ko 쟁점브리핑은 10/17부터 «토크쇼·토론 발췌 ≥ 뉴스 인용»이다. ja도 같은 비율로 갈지 정해야 한다.
