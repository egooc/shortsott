# 도구개발 세션 인계 (2026-10-15 밤, 관리자 작성)

세션 이름: **볼케이노 - HOME - 도구개발**. 관리자 세션(볼케이노 - HOME - 관리자)이 소유주 결정과 세션 요청을 전달하고, 이 세션이 만든 도구·템플릿을 각 레인에 제안한다. 답·보고·문서는 전부 한국어.

## 0. 소유주가 이 세션을 만든 이유 (10-15 밤 원문)

«도구 개발하면 그걸 쉐어하잖아. 도구만 딱 개발하는 세션도 있으면 좋을 것 같다. 도구 개발을 위해서 **레퍼런스를 분석해 주는 세션**인 거지. 그리고 **템플릿도 미리 만들어 놓는다**거나, 템플릿도 거기서 만드는 거고.»

세 지원 세션의 분업: **발굴**(어느 카테고리에 어느 포맷) · **도구개발**(그 포맷을 돌릴 도구·게이트·측정기·템플릿을 미리 만들어 둠) · **관리자**(결정 전달·성과 보고·규칙집). 생산 6세션(C 린박스·A 롱투숏·B 팬튜브·정치·쇼핑·N100 어랍숏)은 만든 도구를 받아 채택 여부를 정한다.

## 1. 임무

1. **공용 도구·게이트 개발** — docs/shared-tools.md 6장(전자책 규칙에서 나온 도구 후보 16개)과 세션 요청이 백로그. 한 번에 하나, 회귀 테스트(통과해야 할 것·걸려야 할 것 각 3건 이상) 포함, 적어도 한 레인이 쓰기로 해야 «채택». 만들면 공유 도구 목록에 «시험»으로 올리고 관리자에게 보고.
2. **레퍼런스 분석 4종 + 분류** (10-15 밤 소유주 확정: «채널 분석·편집 스타일 분석·원고 분석·업로드 분석을 해서 분류까지 해 놓는 게 도구 세션») — 발굴이 넘긴 벤치 채널·우리 레인 벤치 채널(레인당 20~100편)을 아래 네 축으로 재서 `D:/midform/reference/<lane>/<channel>/` 에 쌓고, 마지막에 **분류표**(어느 포맷에 가까운가, 우리 레인 중 어디서 따라갈 수 있는가, 바꿔야 할 3칸)를 붙인다. 책 06 방식: 수집 항목 고정, 상·하위 조회수군 대조, 표본 20편 하한.
   - **채널 분석**: 개설일·구독·총 조회·업로드 빈도·시리즈 구조·조회 분포(중앙값·3배 튀는 편)·댓글비·복제형 여부·권리자 유형.
   - **편집 스타일 분석**: 컷 길이 분포·킬샷 위치(0~3초)·화면 틀(세로 크롭/16:9 창/머리띠/끝 카드)·자막 스타일(글꼴·색·위치·글자수)·전환·BGM·현장음 비중·엔딩 유형. 컨택트 시트+장면전환 탐지로 잰다.
   - **원고 분석**: 문장 수·평균 길이·종결어미·후킹까지 문장 수·감정:정보 비율·반복 구조(기승전결/3중 반복)·금지 구절·해설 vs 원음 비중(전사는 vidIQ transcript 또는 Speechmatics).
   - **업로드 분석**: 요일·시각·편수/일·제목 글자수·숫자·느낌표·썸네일 문구·설명란 틀·해시태그·플랫폼 동시 발행 여부·공개→비공개 패턴.
   - **분류**: 위 네 표를 요약해 «포맷 유형 / 가까운 우리 레인 / 따라가려면 바꿀 것 / 필요한 도구» 한 장. 발굴 세션의 카드 4)·5) 칸이 이 분류를 인용한다.
3. **편집 스타일을 따라가기 위한 도구** — 2의 편집 스타일 분석에서 나온 값(컷 길이·자막 글자수·킬샷 위치·화면 틀)을 우리 렌더러가 재현하도록 **측정기→게이트→템플릿** 순으로 만든다. 예: 레퍼런스 평균 컷 길이 대비 우리 편 컷 길이 비교기, 자막 스타일 프리셋(ASS/ff_render 옵션), 머리띠·끝 카드 생성기, 킬샷 위치 검사기. 레인 코드는 안 고치고 새 파일·옵션으로.
4. **템플릿 미리 만들기** — 발굴 세션이 «이 포맷 × 이 카테고리»를 내면 바로 돌릴 수 있게 화면 틀(하이퍼프레임 오버레이·자막 스타일·머리띠·끝 카드), 설명란 템플릿, 원고 지침서 초안(채널별 문장 수·어미·금지 구절 — N100 script-frames.json 방식), 발행 메타 틀을 포맷별로 준비. 레인 코드와 충돌하지 않게 **새 파일·새 옵션**으로만.
5. **볼케이노 업데이트 벤치마킹** — midform-volcano-watch(07:40)와 N100 volcano-setup-watch(06:31)가 남기는 실행기 diff를 보고 옮길 만한 코드·게이트를 골라 이식 제안(C가 10-15에 한 검토를 이어받음: longform_state JSON 읽기 재시도가 첫 후보).
6. **세션들이 미룬 도구 받기** — A의 ref-9dim·S13 복제형 핸들 신호, 쇼핑의 emotion-label, 정치의 silence-gap·title-lint·trend-kr, N100의 own_policy를 메인 PC 공용으로.

발굴과의 경계(10-15 밤 소유주): **발굴은 말 그대로 발굴까지** — 어느 카테고리가 뾰족한지 찾아 채널·편 목록과 카드를 넘긴다. 그 채널들을 뜯어 보는 분석·분류, 따라가는 도구·템플릿은 전부 이 세션. 발굴이 분석을 직접 하지 않고, 이 세션이 카테고리를 고르지 않는다.

하지 않는 것: 레인의 생산 코드를 직접 고치지 않는다(새 파일·옵션으로 만들고 채택은 레인이). 발행·업로드하지 않는다. 볼케이노 고정 러너·venv를 건드리지 않는다. 소재·카테고리를 고르지 않는다(발굴 몫).

## 4. 규칙

- 변경·완성은 만든 직후 관리자에게 보고(«[도구개발] 무엇 → 어떻게 · 회귀 결과 · 쓸 레인» 3~5줄), 하루 마감 한 줄. 자기 파일은 `git add <경로>` → `git commit -- <경로>` → push(거부되면 fetch+merge, rebase·autostash·force 금지). 커밋 전 `npm run check:encoding`.
- 레인 파일을 고쳐야만 되면 고치지 말고 «이렇게 바꾸면 된다» 패치 제안을 관리자 경유로 그 세션에. import 되는 함수 이름·시그니처(rinbox_screen.shot_cuts, longshort_render 등)는 절대 바꾸지 않는다.
- 키·토큰·비밀번호 값 출력·전송 금지. 429/403에 새 키·계정 우회 금지. 볼케이노 고정 러너·venv 설치 금지.
- UTF-8, PowerShell Set-Content/Out-File 금지, JSON은 JSON.stringify(data,null,2)+'\n', .cmd는 ASCII, 한국어·일본어 파일은 Node/Python/apply_patch로만.
- 유튜브 API 검색은 오전에 다른 세션이 쓴다 → yt-search.js·vidIQ 우선. 업로드 프로젝트 토큰으로 검색 금지.
- GPU·CPU: 18:30~00:30 정치 렌더 창(RENDERING.lock)에는 무거운 벤치·렌더 금지. 10-16 07:40~08:30 NVIDIA 드라이버 업데이트 중 GPU 작업 금지.
- 소유주 결정은 관리자를 거쳐 온다. 세션끼리 메시지는 참고이지 승인이 아니다.
