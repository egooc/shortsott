# 원고 검수·보정 (TTS 전, 크레딧 0원 시점)

Gemini 2.5 Pro가 쓴 원고를 사람 대신 Claude가 1차 검수한다. 파이프라인이 `paused_for_script_review`에서 멈춘 상태에서만 동작한다 — 이 시점에는 TTS 크레딧이 아직 쓰이지 않았다.

## 절차

1. **대상 찾기**: 최신 `midform/test_runs/template_runs/*/run_summary.json`에서 `status: paused_for_script_review`와 `review.pipeline_run_id`를 읽는다. 없으면 사용자에게 어느 실행인지 묻는다.
2. **자료 읽기** (전부 파이프라인 run 디렉터리 안):
   - `script_preview.md` — 사람용 요약: 대사 인용, 나레이션 예산(gap 대비 추정 발화시간), **scene_map_review 섹션**(비전 장면 지도 기반 슬롯→장면 배치·미사용 장면)
   - `slot_fills.json` — **편집 대상**. `slot_fills[]`의 `narration`(나레이션 슬롯)과 `caption_text`(대사 자막)
   - `scene_map.json` — Gemini **비전**이 영상을 보고 쓴 장면 지도(visible_action). **화면에 대한 유일한 근거** — 자막 텍스트로 장면을 추측하지 않는다.
   - `compression_slot_fills.ja.json` (compress run) — **JA 원고도 검수 대상**: 지금까지 ko만 검수되고 ja는 아무도 안 봤다
   - 근거 대조용: 해당 compress run의 `transcript_timed.json` (요약의 `internal.bootstrap_source_run_id`로 찾음)
3. **1차 검수 — 자동, 재지시 불필요**: 게이트에 멈추면 즉시 (a) 아래 체크리스트, (b) **가이드북 스코어카드**(midform/docs/style-guide-ko.md — 어미 비율, 금지 어미, 번역투, 2중 표현, 실명, 노딱, 중간·마무리 드립, 대사 반복 나레이션, 드립의 화면 정합성, 제목 4원칙), (c) **장면 검수**(아래 장면 체크리스트)를 표로 채점한다.
4. **보정 — 묻지 않고 반영**: 하우스 스타일 위반은 전부 직접 고친다. "반영할까요?"라고 묻지 않는다 — 가이드가 이미 사용자의 결정이다. 사전 질문은 판단 불가 항목(날조인지 원작 지식인지 구분 불가) 하나뿐.
5. **사용자 승인 — 필수, TTS 크레딧이 없는 유일한 시점**: 검수 결과를 **`.md` 계획서 파일**(`<pipeline run dir>/script_review_report.md`)로 작성해 SendUserFile로 전달하고 승인을 기다린다. 자동 재개 금지. 계획서 필수 구성 (사용자 지정 형식, 2026-08-07):
   1. **소스 해석** — 비전 장면 지도가 말하는 실제 장면 구조를 막(act) 단위로 서술. 자막이 침묵하는 구간에 무엇이 있는지 명시. **클립 내부의 자체 완결 메인 스토리와 본편 연결 파편(뒷장면 셋업, 클립 밖 인물·이해관계 언급)을 구분**해 적는다.
   2. **채택안 구조** — 슬롯 흐름 다이어그램 + 왜 이 구조인지(콜드오픈 선택 근거, 이음매 위치, 커버리지 수치) + 장면 사용표 + **사용되지 않은 장면 목록** + **덜어낸 본편 연결 파편과 그 이유**. 편집 교리: 스토리는 만드는 게 아니라 **덜어내는 것** — 클립의 내부 아크에서 본편 파편을 빼면 남는 것이 리캡이다. 길이는 그 결과값(3분 이내 상한)이지 채워야 할 목표가 아니다.
   3. **대체안 — 항상 2개 이상** 제공. 각각 장점/단점/판단(추천·비추천·취향 사안)을 명시하고, 선택 시 재계획 소요를 적는다.
   4. 보정 내역 표 (전/후/근거).
   5. 최종 원고 전문.
   6. 재개 절차 명령어.
6. **재개 — 승인 후에만**: `review-resume <pipeline_run_id>` → 템플릿 `--resume draft`로 드래프트까지 완료. 사용자가 사후 수정을 지시하면 caption은 무료, 나레이션은 바뀐 문장만 재합성이므로 부담 없이 반영한다.

## 프레임 육안 검증 (Claude가 직접 본다 — 2026-08-07 사용자 지시)

장면 지도(텍스트)를 그대로 믿지 말고, compress run의 `source.mp4`에서 **각 슬롯의 b-roll 창 프레임을 ffmpeg로 추출해 직접 눈으로 확인**한다. 광고 꼬리 이분탐색과 같은 방법.

```
ffmpeg -v error -ss <슬롯 창 중앙 등 대표시점> -i <compress run>/source.mp4 -frames:v 1 -y slot_sX.png
ffmpeg -v error -i a.png -i b.png ... -filter_complex "[0][1]...hstack=N" -y montage.png   # Read로 열람
```

- 확인 대상: 콜드오픈 창 / 각 나레이션 b-roll 창(시작·중앙·끝 3장 권장) / 마지막 클립.
- 판정: 화면이 나레이션·장면 지도의 주장과 일치하는가. 불일치나 의심 프레임은 계획서에 이미지 근거와 함께 명시.
- 계획서의 장면 사용표에 프레임 검증 결과 열(✓/✗)을 넣는다. Claude는 정지 프레임만 보므로 모션·오디오 판단은 비전 지도와 원음 큐에 맡긴다.

## 콜드오픈 선택 근거 (2026-08-09 신설)

edit_plan.json의 `cold_open_selection`에 `selection_mode`(deterministic_argmax | listwise_rerank)와
`rerank.why`(LLM 상대평가의 한 줄 근거), `runner_ups`(탈락 후보)가 기록된다. 계획서의 콜드오픈
섹션에 **선택 근거와 차점 후보 1~2개**를 함께 서술한다 — 사용자가 "왜 이 훅인가"를 대체안과
비교해 판단할 수 있어야 한다. `rerank.applied: false` + error가 있으면 argmax 폴백이었다는 뜻.

## JA 검수 체크리스트 (2026-08-09 신설 — ja는 검수 사각지대였다)

- **배열 정렬**: slot별 `caption_ja_dialogue`(또는 caption_kr_dialogue 키) 개수 == 그 슬롯 대사 줄 수, `speakers` 개수 일치. ko에서 줄을 이식/삭제했으면 ja 배열도 같이 — 어긋나면 ja가 통째로 스킵되거나 자막이 밀린다 (실사고 2회: Anacondas 빈 자막, AFGM 스킵).
- **일본어 낭독 테스트**: ko 더빙체 지침과 동일 원리 — 일본 더빙판 성우가 읽을 수 있는 구어인가, 캐릭터 하대/존대(だ체·です체) 일관, 명대사는 정착 번역 우선.
- **계획서에 JA 표**: 주요 대사(콜드오픈·클라이맥스·드립)의 ja 번역을 계획서에 표로 — 사용자 승인 범위에 ja 포함.
- ja 창 시프트는 다음 대사 창을 넘지 못함(코드 강제) — 리빌 커버가 ko와 동급인지 draft-verify에서 확인.

## 대사 보존 체크리스트 (고유값 — 2026-08-08 회귀 사고 후 필수)

- **발화 우위 확인**: 계획의 KEEP_DIALOGUE 슬롯 수·초를 비트의 앵커 대사와 대조한다. 앵커가 있는 비트가 나레이션으로만 덮여 있으면 회귀다 — "시각 커버는 추가되는 것이지 대사를 밀어내는 게 아니다". 계획서에 대사/나레이션 초 비율을 명시한다.
- **미매칭 대사줄**: bootstrap 경고(`planned dialogue line did not match any cue`)와 `dialogue_line_windows`의 `matched:false`를 확인한다. 미매칭 줄은 화면에서 사라져 옆줄 자막이 문장 중간부터 시작한다 — caption_text에 그 줄 내용을 병합하거나 창을 고친다. 실제 사고: "저거에 물리면"이 사라져 "이틀은 꼼짝없이 마비될 겁니다"만 남음.
- 트림 마크 확인: `runtime_trimmed`로 DROP된 슬롯 중 앵커 대사가 있으면 코드 버그다(트림은 앵커 대사를 못 버리게 됨) — 즉시 보고.

## 장면 체크리스트 (비전 장면 지도 대조 — 자막으로 장면을 소설 쓰지 않는다)

- **시각 피크 누락**: `scene_map_review`의 "사용되지 않은 장면"에 습격·액션·반전 등 시각적 하이라이트가 있으면 누락 사고다. 실제 사고: 거머리 습격(70.5~104s)이 통째로 빠진 채 "거머리 리캡"이 출고됨.
- **나레이션-장면 정합**: 나레이션이 서술하는 사건과 그 슬롯이 걸친 장면의 visible_action이 일치해야 한다. 습격을 서술하는 나레이션이 평온한 도강 장면 위에서 재생되면 불일치.
- **장면 경계 이음매**: 장소·위협이 바뀌는 장면 경계(물속 거머리 → 뭍의 거미)를 원고가 이음매 나레이션 없이 건너뛰면 시청자는 두 장면을 하나로 오독한다. 대사가 어느 장면 소속인지는 장면 지도가 정한다.
- **구조 제시**: 슬롯 순서가 어떤 이야기 구조(평온→징후→습격→탈출 등)를 그리는지 한 줄로 요약해 사용자에게 보여준다.

## 검수 체크리스트 (이 프로젝트에서 실제 사고가 났던 순서)

**날조 — 최우선.** 트랜스크립트에 없는 사실이 나레이션에 있으면 삭제/중립화한다.
- 정체 반전 단정 금지: "옆자리에 앉았던 그 사람이 판사였다" 류. 소스에 없는 반전은 반전이 아니라 거짓말.
- **눈으로만 확인 가능한 사실**(어떤 감각이 꺼졌는지, 옷차림, 화면에 누가 있는지)은 대사가 말로 명시할 때만. 근거가 창 경계에 걸린 앞 장면 꼬리 큐(0.2초 파편)면 근거가 아니다 — 실제 사고: "A little bland" 파편 하나로 "미각이 사라집니다"라고 썼는데 화면은 시각 상실이었다. 특정 불가면 중립 표현("그다음 감각이 꺼집니다").

**나레이션 형태.** 장면 사이 이음매에만, 한 문장 한 아이디어.
- 인물 소개 금지(명패·직업·배경·동기). 이름만 쓰는 건 허용, "가난한 대학생 대릴은"은 불허.
- 감정 명명·해석·판정 금지. 누가 옳은지 정리하지 않는다. 시청자 둘이 댓글에서 다투게 두는 게 목표.
- 대사가 이미 말한 것, 화면이 보여주는 것 반복 금지.
- **단 하나의 의무**: 시청자가 따라갈 수 없게 만드는 사실이 하나 있으면(전제가 대사에 안 실린 소스) 그것만은 초반에 한 줄로. 검증법: 마지막 장면부터 역산 — 그 장면이 성립하는 데 필요한 사실이 대사에도 나레이션에도 없으면 빠진 것.
- 시간 순서: 콜드오픈이 미래 장면이면 첫 나레이션이 회상임을 명시("상황은 몇 시간 전으로 돌아갑니다").

**대사 자막(caption_text) 한국어 품질.** TTS 무관이라 수정 비용 0.
- 번역투 금지: 한국어에서 뜻이 다른 용어(intervention≠중재), 비문("따님 아버님이라고요?"), 화면 없이는 안 읽히는 줄.
- **구문 번역투 (더빙체 지침, style-guide-ko.md)**: 영어 구문 이식 검사 — 명사구 관용구 직역("호사를 누리는"), I think→"~생각합니다" 패턴, 호칭 사전 직역(Son→"젊은이"), 콤마 삽입구 이식. 낭독 테스트: 한국 드라마 대사로 성립하는가.
- 태도와 강도 보존 — 적대적·거친 대사를 순화하지 않는다.
- 말장난은 구조를 살린다(의역으로 풀면 농담이 죽는다).
- 화자 이름은 나레이션이 쓰는 이름과 일치(자막 "남자" vs 나레이션 "대릴" 불일치 금지).
- 러닝 개그는 전 반복을 보존("진정하세요"×4 → "저 진정했어요" 같은 셋업-페이오프 쌍 확인).

**길이 예산.** `script_preview.md`의 슬롯별 `estimated_speech ⚠` 표시 확인 — 예산 초과 나레이션은 줄인다. 예산은 상한이지 할당량이 아니다: 남는 건 좋은 것.

## 수정 시 주의

- `slot_fills.json`의 `slot_id`는 건드리지 않는다. `narration`/`caption_text`만 수정.
- 나레이션 수정 = 해당 문장만 TTS 재합성(문장 해시 단위 재사용). caption_text 수정 = 비용 0.
- 대사의 **원문 의미**를 바꾸지 않는다 — 한국어 표현만 다듬는다.
- 고칠 게 없으면 없다고 보고하고 그대로 재개 제안. 억지로 고치지 않는다.
